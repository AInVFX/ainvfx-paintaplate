# AInVFX Paint a plate: architecture

This document explains what Paint a plate does, how it is built and where each part lives, for anyone who maintains the code. It describes version 1.11.17. `TESTING.md` covers the tests.

## 1. What Paint a plate does

A **plate** is the source footage of a shot: a video file (MP4, MOV, MKV, MXF, WebM, or an animated WebP or GIF) or an image sequence (a folder of EXR, PNG, TIFF or DPX frames, or one sequence in a folder named by its frame pattern, such as `shot.####.exr`). You paint on the plate's first frame, and the change carries through the whole shot. There are three tools:

- **Paint** adds something new where you paint, from your words: a fire, a boat, a lamp.
- **Clean** removes an object, and the clean plate comes back behind it. The code's name for the tool is still `erase`. With **Whole object** on (the default), SAM 3.1 finds the whole object under the strokes, by its name when you type one.
- **Light** relights the scene from where you paint, in the colour of the brush.

Generate (the button at the end of the prompt bar, or Enter) starts an edit and its render. FLUX 3 Image Klein makes the edit on the first frame. The shot then renders by itself: LTX 2.5 carries the edits through every frame, SAM 3.1 tracks the changed areas, Follow Matte keeps every generated element inside the matte, and the result is composited onto the plate. A quick preview comes first, then the full-size passes, then the **review**: the full-size composite at the plate's own quality, which the viewer plays from then on. Generate never makes a result twice: an edit whose strokes, words, seed and Whole object switch have not changed keeps its result.

**Export** writes the result for compositing software, only when you press it: the plate's own format (file type or codec, bit depth, frame numbers, colour tags, timecode, audio, EXR layers), with every pixel outside the edits the exact source pixel, and the matte. Nothing is written for compositing software while you iterate.

**Colour** is managed with OpenColorIO, as OpenRV manages it. The config is the one `$OCIO` names, as in RV, else OCIO's built-in studio config (ACES 2.1, with the camera log spaces). Each plate has one colour space in that config, its **file colour space**: read from the file when the plate opens, and changed from the right-click OCIO menu. The viewer shows the plate through a display and a view; the models see the plate converted to the model space; the export converts the edited pixels back to the plate's colour space.

A **fluid shot** starts from a blank plate instead. You paint flat colour keyframes: light grey for smoke, white for steam, orange and yellow for fire, and optional flat zones for sky and ground. AInVFX's ainvfx-fluid IC-LoRA, trained on synthetic data (dataset `AInVFX/ainvfx-fluid`), turns them into smoke, steam, fire, explosions, dust, fog or clouds in one LTX 2.5 pass. The result then becomes the plate for every edit.

**Keys.** P picks Paint, C picks Clean and L picks Light. X is the eraser, which rubs out strokes: it lasts while X is held during a drag, and a tap shorter than 0.3 s switches it on or off (`logic.eraserAfterKey`; the code's name for it is still `rub`). B and E are free.

## 2. Words used here and in the code

| Word | Meaning |
| --- | --- |
| Plate | The source footage of a shot. `warmAll` reads the card from `/system_stats`, sets `S.memoryProfile` and loads what that profile names (section 15). |
| First frame | Frame 0 of the plate, where every edit is painted. In the code, `S.original` is the plate's first frame in the model space, and `S.hero` is the first frame with every active edit stacked on it. |
| OCIO config | The OpenColorIO config in use: `$OCIO`, else a built-in config (`ocio://studio-config-latest` by default). `S.ocio.config` names it. |
| File colour space | The colour space a plate's values are in, by its name in the OCIO config (`S.plate.cs`). RV calls it File Color Space, and the OCIO menu shows it as « Plate colour space ». The viewer, the models and the export all use it. |
| Model space | The sRGB-encoded Rec.709 the models were trained on: the config's `sRGB Encoded Rec.709 (sRGB)` (alias `srgb_tx`, role `texture_paint`). In workflows, `@model`; `@linear` is the same space in linear light. |
| Display and view | How the viewer shows scene-linear values on the screen, such as `sRGB - Display` and `Un-tone-mapped`. The viewer only: they never change a result. |
| Edit | One change painted on the first frame: its tool (paint, erase or light), its strokes, its words and its seed. The History panel lists the edits, numbered from 1 at the bottom. |
| Draft | The edit being drawn, before Generate (`S.draft`). |
| Current edit | The edit that new strokes, new words and the Whole object switch change: the edit just started, or the one picked in History (`S.selected`). The Editing tag in the prompt bar names it. |
| New edit | The action that closes the current edit, so the next strokes start a separate one: the N key, the button at the end of the prompt bar, or the right-click Edit menu. Picking another tool does the same. |
| Generate | The button at the end of the prompt bar, or Enter: it starts the draft or the changed current edit, then the render. Pressed with nothing changed, it runs nothing. Ctrl+Enter tries another seed. |
| Patch | The result of an edit: the new pixels of the first frame, as an RGBA image. |
| Pass | One run of a model. A Klein edit runs two: the edit preview, at 768 px on the long side, then a full-size pass. |
| Working size | The size edits are made at: the plate's size, at most 1920 px on the long side, in multiples of 32. |
| Preview size | The size of the shot preview, the quick render you watch first. Fast (640 px on the long side) is the default; the menu offers other sizes computed from the plate, Full, and Off, which renders the full size alone. |
| Review | The full-size composite at the plate's quality, made right after the full-size passes. A video plate's review is a movie of its own values; an image sequence's review is also half-float EXR frames the viewer reads at full precision. Workflow `review`. |
| Export | The result written for compositing software, only when Export is pressed. Workflow `export`. |
| Matte | A black and white mask per frame: where an edit changed the shot. |
| Clean plate pass | The plate without the objects that Clean removes, in every frame (the clean plate), made by LTX 2.5 with Lightricks' in-outpainting IC-LoRA. Workflow `clean`; at full size, in Lightricks' two stages: `clean` at half the working size, then `cleanup`. |
| Shot | The plate regenerated by LTX 2.5 with WepeNerd's Ripple IC-LoRA, from the edited first frame. It carries paint and light. Workflow `shot`. |
| Composite | The shot's new pixels inside the mattes, over the plate's own pixels everywhere else. |
| IC-LoRA | A LoRA for LTX that reads a reference video next to the prompt (an in-context LoRA). |
| Prompt writer | FLUX 3 Image Klein's own prompt upsampler (Qwen 3.5 9B). It writes each edit's caption in Black Forest Labs' format. |
| Workflow | A ComfyUI graph in API format, in `web/workflows`. The page runs every step of its work as one. |
| Slot | A named input of a workflow that the page fills before it posts it: a path, a seed, a caption, a colour space. |
| Job kind | The group a posted workflow belongs to: `edit`, `snap`, `prefetch`, `warm`, `fluid`, and the render's kinds `clean`, `shot`, `matte`, `comp`, `review` and `export`. A cancel stops jobs by kind. |
| Hint | A sentence of the status line that says what to do next: `status(text, "hint")`. It never goes to the log (design rule 12). |
| Stop | Esc, or Stop beside Generate: what generates stops, and no job is posted until Enter (`S.halted`, design rule 13). |
| Layer | An edit, in History's order. While an edit is changed, the frame shows it and the edits under it (design rule 14). |
| Memory profile | What the page does on the card it runs on: `small` under 24 GB of VRAM, `medium`, `large` from 60 GB (`S.memoryProfile`, section 15). |
| Example plates | The synthetic plates of the Hugging Face dataset `AInVFX/ainvfx-paintaplate`, which `get_plates.py` downloads into `input/plates`. |

## 4. Design rules

These rules keep the code small and easy to change. Follow them in every change.

1. **All GPU work is a ComfyUI workflow.** The page loads a workflow file, fills its slots and posts it. The 14 Paint a plate nodes only do what core ComfyUI cannot. So the app runs on any ComfyUI, and a Comfy API deployment stays possible.
2. **Workflows are generated.** `tools/build_workflows.py` writes `web/workflows`. Nobody edits the JSON by hand: a test fails when the files and the generator disagree.
3. **Each workflow describes itself.** In each node's `_meta`, `slots` maps the node's inputs to slot names, `output` names an output the page reads, and `progress` marks the node whose progress bar stands for the whole workflow.
4. **Optional links.** Some links exist only when the page has something to send: a matte to composite with, words to search by, a relit frame, an image sequence's review frames. When their slots stay empty, the page drops the link and every node that fed it. The rule is written twice, as `OPTIONAL` in `logic.mjs` and in `build_workflows.py`, and a test keeps the two equal.
5. **Pure code is tested without heavy dependencies.** `plateio.py`, `mathops.py` and `ocio.py` need neither torch nor ComfyUI. Every module of `web/` except `app.mjs` and `canvas.mjs` runs in Node, with its tests in `tests/js`. `nodes.py` only converts tensors and calls them; `routes.py` is plain functions plus `setup()`.
6. **One edit at a time.** A stroke goes to the draft, else to the current edit if it has the same tool, else to a new edit (`strokeTarget` in `logic.mjs`). Another tool, or New edit, closes the current edit (`toolEndsEdit`). Undo keeps the current edit while it exists.
7. **Nothing made is lost, and nothing is made twice.** Changing the edit being generated (strokes, words, the switch) stops its Klein pass. No render stops for that, nor for a bypass, an undo, a removal or a new edit: renders go on, and what they make stays. Results are kept per set of edits and per preview size (`S.renders`, keyed by `S.heroKey`), and what the erases make per set of erases (`S.erases`). Every finished job is also recorded in the job index on disk (`routes.py`, `output/paintaplate/jobs`), by the server's build (`routes.build_parts`: the pack's Python files, ComfyUI's version and commit, ComfyUI-LTXVideo's commit, or the hash of its Python files when it is not a git clone, and each model file's name, size and time; the line that ComfyUI's log gets at its start names that pack by its commit, or by its version and « files <hash> (not a git clone) »), the hash of its workflow file, the plate (path, size and time) and its values. A job with the same hash takes those files back instead of running, in this session or a later one on the same machine. A job is recorded only when every file it made is in the output folder (`recordable` in `comfy.mjs`, the rule `routes.write_job` enforces). A render of fewer edits, after a bypass or a removal, takes the frames of an earlier render of more edits when every edit left out is far from those kept and no light is involved (`logic.donorFor`, `donorOf`): only its tracking and composites run, and the Render panel shows the steps taken as "from v<n>". Render in full makes its own shot, with the same edits and seeds. After a change of code or of a model file, every job of a scene runs again once: a result made by other code or other weights never comes back. A new version number alone changes nothing. A page left open while ComfyUI restarts on another build asks for a reload, and keeps no index until then (`comfy.indexParts`, `comfy.onBack`).
8. **One colour space per plate.** The plate's file colour space is a name in the OCIO config. The viewer converts from it, the workflows convert from it to the model space, and the export converts the edited pixels back to it. Changing it makes the first frame and the edits again in it; the job index keeps the earlier results, so switching back takes them at once.
9. **Previews may trade quality for speed. The review matches the plate, and the export never trades.** The review of a video plate is a movie of its own values at the working size; the review of an image sequence is also its half-float EXR frames, which the viewer compares with the plate's own frames at full precision.
10. **Paths stay inside ComfyUI.** Every path from the page resolves under ComfyUI's input or output folder (`folders.plate_path`), symbolic links are refused, and absolute paths need `PAINTAPLATE_ALLOW_ABSOLUTE=1`.
11. **One home per value.** Sizes, delays and budgets: the tuning block at the top of `app.mjs`. Model files: the constants at the top of `build_workflows.py`. Tested ComfyUI and ComfyUI-LTXVideo commits: `tools/pins.sh`. Model files and revisions: `get_models.py`.
12. **The log says each fact once, and the status line says what to do next.** The log records what happened, one line per fact: a size, a frame count, a memory figure or a file name appears in one line only. A job writes one line when it ends, with how long it took; it writes more only when it waits over a second in the queue, fails or is stopped. A sentence that tells the person what to do is a hint, `status(text, "hint")`: it shows in the status line and stays out of the log. `told(fact, next)` writes the fact to the log once and shows it in the status line with what to do next; `stopped(fact, next)` does the same for a page that cannot start, as an error. Memory is written in GB as bytes / 2**30, rounded: a 16 GB card reads « 16 GB » everywhere. A plate that opens writes two lines: what it is (its size, its frames, its bit depth, its colour space and the seconds the open took), then the working sizes. Every message a person reads has one form: the thing and its state first, then the figure; a long message is a headline with detail lines under it, two spaces in; every message ends with a full stop. A log message takes its colour from its words (`logic.logLevel`): red when one of its lines starts « Error: », for work that stopped, and amber when one starts « Warning: », for something to check. A failure writes one fact in the log, and the status line adds what to do (`explained`, `logic.plainError`).
13. **A stop stops everything.** After Esc or Stop, nothing else starts until Enter (`S.halted`): an edit that waited keeps its turn, a stroke asks for nothing, and what finished is kept. A job of a kind the stop ends (`STOPPED` in `app.mjs`) is not posted while the stop is in force: `run()` in `comfy.mjs` asks the page's rule (`onStop`), so work that was between two jobs, such as a render step that uploads its images, ends as it does when its job is cancelled.
14. **Edits are layers.** While an edit is changed, the frame shows that edit and the edits under it (`layered`, `logic.hiddenAbove`). The edits above it are hidden and History dims their rows: they are likely to be generated again.
15. **One set of workflows for every card.** The memory profile only fills slots and decides what loads at start (`MEMORY` in `logic.mjs`, section 15).

## 5. The life of an edit

1. **Open a plate** (`openPlate`). The route `/paintaplate/stat` reads the plate's size, time and spec, and guesses its file colour space in the OCIO config (`ocio.guess`: the EXR's chromaticities or the video's colour tags, then the config's file rules). The `ingest` workflow decodes the plate once and holds it once: no node makes a second batch of it. It converts the first frame alone, with the whole plate's peak (`peak_of`), and saves it in the model space (at most 1920 px on the long side). Save Movie makes the playback proxy from the plate itself, one frame at a time. The plate spec goes out as text. A video plate's proxy keeps its own values at the working size, so the viewer converts it as it converts the plate; an image sequence's proxy holds log values (ACEScct in the built-in config) at 960 px, for playback while its own frames load. The page then sets its sizes: the working size, 768 px for the edit preview, 960 px for tracking (640 px for erase mattes) and the shot preview's size. An image sequence plays at 24 fps, or at the rate its EXR frames say (`framesPerSecond`, read by `plateio.exr_rate`).
2. **Paint.** Each edit draws on two canvases: `paint` (what Klein sees, for a paint) and `mask` (where the edit may act). `strokeTarget` decides which edit a stroke joins. I, or the pipette by the swatches, picks a colour for the brush in every browser (`pickColor`): the next click on the frame takes its colour (`pickAt`, `pickedColor`). On the first frame the pick reads the frame's own values, the ones Klein reads, with the paint in progress over them; on another frame it reads the pixels on show. A paint stroke shows at its own colour, through OCIO and the colour tools as the picture does (`strokes`), so a stroke of a picked colour cannot be told from the picture where it was picked, in any view. The browser's own eyedropper read the screen and was dropped. `tests/ui_picker.py` checks it in any browser.
3. **Prepare while the strokes rest** (`prepareSoon`, then `prefetch` and `prepare`). `takeInputs` reads the words and the Whole object switch into the edit. For an erase with Whole object, the `snap` workflow asks SAM 3.1 for the object by name and from up to five stroke points, and `pickObjects` keeps the right masks. Then the `prompt` workflow asks the prompt writer for a caption, and `reconcile` puts the page's boxes back into it. An erase sends one locked box per painted part (`paintBoxes`), and a caption that removes something the paint does not cover gives way to the page's own (`erasesPaint`). When that happens to an erase with no words, SAM 3.1 finds the other object by the writer's name for it (`logic.removedNames`, the `snap` workflow with words alone), the writer's box is cut to the part that holds the most of the object under the stroke and almost none of the other one (`logic.boxWithout`), and the writer is asked once more (`leaveOut`). When SAM 3.1 finds nothing to leave out, when no such box keeps half of the object, or when the second answer still removes another object, the page asks for the object's name before Klein runs, and nothing renders (`logic.asksName`); with words, the page's own caption carries them. An article typed before the name is dropped, so a request never reads « Remove the the barn ». An erase with no words, painted in one part, asks the prompt writer with one box: the stroke and what most of SAM's masks hold, with no margin (`logic.coreBox`, `logic.writerBoxes`). A wider box took in the horse's nose beside the barn, and the writer removed the horse. Other edits keep one box per painted part. A new stroke cancels this work.
4. **Run the edit** (`launch`, then `generate`) when you press Generate (Enter). An edit whose strokes, words, seed and switch match a result it already made takes that result back (`reuse`, up to `RESULTS_KEPT` results per edit). Ctrl+Enter tries another seed. The `edit` workflow runs twice: the edit preview at 768 px on the long side (16 steps, denoise 1, with live previews inside the strokes), then a full-size pass from that result (8 steps, denoise 0.35). The result is the edit's patch. For an erase, the full pass ends in Level Fill, which levels Klein's fill with the background around it: left in, a pale imprint of the removed object became smoke in the clean plate pass. The `edit` workflow saves its outputs to the output folder, so the job index finds them later. After an erase's full-size pass, the page compares the first frame with the frame under the edit inside the object's mask (`logic.erasedShare`). When the check finds the object still there, the page asks first, in its one question dialog (`heldBack`, `logic.leftLines`, `ask`): « Render anyway », clicked or by Enter, keeps the first frame and renders its shot; « Cancel » or Esc drops the result and leaves what to do next in the status line (`leftHint`). History's row is marked as the question opens. The check holds an erase back when: under 30% of the object moved by more than 24 levels, or its edges held above 0.85 (`logic.eraseCheck`). The first rule, under 2% at 12 levels, passed a barn that Klein had only recoloured.
5. **Stack the first frame** (`recompose`). Active patches stack on `S.original` to make `S.hero`. When an edit changes, the edits above it run again only if they depend on it (`dependsOnChange`: one of the two is a light, or their footprints overlap on a 96-cell grid).
6. **Render** (`idle`, then `pipeline`), from the render queue. Every set of edits shown is a render (`want`), made from a copy of its edits (`freeze`). One step runs at a time (`pickRender`, `logic.nextRender`): every preview before any full size, every full size before any export, the set on show first, then the most recently shown, for the last `RENDERS_WANTED` sets. A render gives way between steps (`YIELD`) and resumes later where it stopped. Nothing stops a step but Generate, which stops a full-size or export step in its first half (`preempt`, `logic.stopsForEdit`); that step runs again later. `plan` skips the steps an edit set does not need:
   - `matte` at 640 px tracks each erased object (SAM 3.1, then Follow Matte: one matte per frame even when SAM returns none, the last matte where SAM loses the object, and no other object SAM finds by itself);
   - `clean` makes the clean plate pass: each erased area as blocks of LTX's 32 px grid, grown by one block, and a prompt that describes the scene as it stays (`erasePrompt`), never the erased object;
   - `shot` regenerates the shot over the clean plate (or over the plate when nothing is erased), for paint and light;
   - `matte` tracks each painted area, and Follow Matte adds every pixel the shot changed near it, compared with the plate the shot was made over. The paint matte starts from the pixels the edits changed on the first frame (`changedMask`), not from the whole paint zone. SAM 3.1 is prompted with the paint zone and returns that zone on its first frames (10 to 13 on the cow): on those frames the matte of an object that stands still is its place of frame 0, moved with the background. When something the plate holds passes in front of a painted object that stands still in the scene, the matte leaves out what stands in front, is empty while the object is hidden, and takes the object again where it comes out; An erase reads the frames it tracked as the plate: an erased object that stands still and passes behind something leaves the matte while it is hidden, and the matte takes the tracker's mask again where the object comes out. A piece of the tracker's mask that lies mostly on what the plate holds in front is left out, for a paint as for an erase. When less than a quarter of the object's place holds the object, a found area that reaches beyond the place's margin is left out whole, and once all that was found has left the place no last matte holds. A painted object that leaves its place for good is lost: from the first frame where all that was found has left the place, with the object never seen there again, the matte holds nothing, and the summary warns. The tracker's mask counts as the paint zone only when it lies mostly inside the zone. A paint over a Clean edit: the `matte` workflow gives Follow Matte the Clean matte and how far the composite moves its edge, its grow plus its feather (`erased`, `erased_edge`). Inside the Clean matte so grown, a change joins the paint's matte only where it touches the SAM mask, within a zone of it; painted smoke that drifts over the cleaned place away from its source is cut there. The summary is a headline, the warnings (an object that left its place; a matte above 3 times the object, with its frames), then one line per rule that acted, the flicker last.
   - `comp` makes the composite at the preview size, in the model space.

   Then the same passes run at full size, without waiting for anything: at full size the clean plate pass runs in Lightricks' two stages, `clean` at half the working size (the preview's own pass when the preview is that size), then `cleanup`, 2 steps at full size. The viewer plays the full-size shot as soon as it is made: the preview size can lose an effect that the full size keeps. With Preview size: Off, the four preview steps join the render's skip set (`plan`): the render starts with the full-size passes, the Render panel lists no preview row, and the viewer keeps the plate until the full-size composite. Last comes `review`, the full-size composite in the plate's own colour space, which the viewer plays from then on (`r.review`; for an image sequence, its EXR frames too, `r.reviewFrames`).
7. **Export**, when you press Export (`S.wantDownload`). The `export` workflow makes the same composite, then Save Plate writes it in the plate's format with the exact source pixels wherever nothing changed (a video plate's own YUV samples), and the matte frames, beside the review. The route `/paintaplate/download` zips the parts ticked in the Export dialog. A render that is not on show never exports.

On cards with 24 GB or more, preview passes show a live preview: every second step, the Live Preview node decodes the frames LTX predicts into a looping WebP.

## 6. Colour, as OpenRV does it

1. **The config.** `ocio.py` loads `$OCIO` when it is set, else a built-in config; the page can switch among them (`/paintaplate/ocio` lists them). It never opens a path the page sends.
2. **The viewer** (`display.mjs`). Each source is drawn through one WebGL2 program, in the order OpenRV chains its nodes under OCIO: `ocioIn` (the source's colour space to scene-linear, as OCIOFile), the colour tools in scene-linear as RVColor (`ColorIPNode.cpp`): gamma first, then one matrix built in RV's order (invert, exposure, contrast about 0.5, hue, saturation), then `ocioOut` (the look, then the display and view, as OCIOLook and OCIODisplay), then the channel shown as grey, picked from the display values, as OCIODisplay floods a channel after its OCIO function. OCIO writes `ocioIn` and `ocioOut` as GLSL ES 3.0 on the server (`/paintaplate/ocio/shader`), with their lookup tables as float textures. A program is made once per colour space and view, so changing either applies at once, also while the shot plays. When the whole chain changes nothing (an 8-bit frame through an identity view, the colour tools at their defaults), the frame is drawn as it is.
3. **What each source is in.** The plate's own frames, a video plate's proxy and its review: the file colour space. The first frame, the patches, the live previews, the preview composites, the shots and an image sequence's review movie: the model space. An image sequence and its review are read as RGB half floats (`DeepFrames`, `/paintaplate/frames`), around the playhead, as OpenRV's cache keeps an EXR's half floats.
4. **The menu.** Right-click, then OCIO. Two headings: « Plate (affects generation) » and « View (display only) ». Under the first, « Colour space » (RV's File Color Space), a tree by colour-space family: its line ends with « from file » for the file's own value, or « override » once the person chose another (`logic.plateSpaceLine`). Under the second: View (the views of the display in use), Display, and Look when the config has looks. Then Config. A new colour space or a new config regenerates the edits, so the page asks first when an edit has a result: « Changing the plate's colour space affects generation: 1 edit will be regenerated. Continue? », with Continue and Cancel (`logic.remakeQuestion`). The page has one question dialog, `ask`, and one question at a time: a question that comes while another is open waits for its answer. In the plate's tree, the config's family « Display » reads « Display-referred » (`logic.plateFamily`); RV and Nuke show it as « Display ». View, Display and Look never ask. Each line shows its value. RV binds no key for OCIO; neither does Paint a plate. The display, the view, the look and the config are kept for the next session.
5. **The workflows.** Color Space (OCIO) converts the plate to the model space as core ComfyUI's Convert Image Color Space made sRGB: values above 1.0 tone-mapped with the batch's peak, then a gamut compression (`ocio._into_model`). Out of the model space, values are decoded as they are. Relight Transfer works in `@linear`.

**SDR to HDR** (on whenever its files and nodes are found: `HDR_ON` in `app.mjs`, `?hdr=0` turns it off). The `hdr` workflow is Lightricks' official LTX 2.5 SDR-to-HDR graph: the shot mapped from sRGB to ACEScct by core Convert Image Color Space as the IC-LoRA's guide, fixed scene embeddings for the prompt, CFG 1, 8 distilled steps, and a tiled decode by the video VAE, which core's VAE Loader loads and core's VAE Compute Dtype sets to compute in float32. Color Space (OCIO) then turns the decoded ACEScct codes into ACEScg scene-linear values with the config's own conversion, each frame written into one array (`ocio._fill`), and Keep Black takes the SDR shot as loaded, converts each of its frames as it uses it and lets no value fall below 0. The frames are saved as half-float EXR in ACES2065-1 (the file rules' space for EXR). The page runs it after the full-size shot (`step(r, "hdr")`) when `logic.wantsHdr` says so: no light edit, and the rule that follows. It runs on its own for new content on a plate that holds values above 1.0 (`logic.wantsHdrFor`, `holdsHdr`); on any other plate only when Deliver's bit-depth pass asks for it, and then the render key gains `|hdr`, so each setting keeps its renders. The switch near the render steps is gone (Adrien, 3 Nov): the rule and Deliver cover both of its cases. A plate holds values above 1.0 when its samples are float or when its colour space decodes code value 1.0 above 1.0 (`logic.holdsHdr`; `headroom` comes from the stat route: a log encoding, PQ or HLG), video or not, and then it exports in its own format with no extra files (Adrien, 3 Nov). Otherwise (an SDR video, an integer sequence in sRGB or a linear encoding) Deliver's bit-depth pass converts it on purpose, asked first (`askDeliverHdr`, `#deliver-confirm`), and the result becomes an EXR sequence (`logic.exrResult`). Its review also writes half-float EXR frames in the plate's colour space with values above 1.0 kept, which the viewer reads at full precision as an image sequence's, and its export drops Save Plate (the optional link `export_plate`) for half-float EXR frames in ACES2065-1 (`export_exr`). `review` and `export` load its frames, convert them to the plate's colour space and fit them with HDR Match (`mathops.hdr_match`): one gain per channel, the median ratio to the plate's own values over the untouched mid-tones (plate luminance 1/64 to 0.71) of the whole shot. A gain changes no ratio, so the range SDR to HDR made above the plate's white stays for grading. Without HDR frames the `hdr_shot` link goes and HDR Match passes the SDR shot through. A 16-bit blank plate runs its fluid shot through `hdr`; the EXR frames become the plate under the edits, and they say the blank plate's frame rate.

**SDR to HDR's temporal tiles.** The flicker of 29 Oct had two causes. In the files: Lightricks' distilled graph decodes in 64-frame temporal tiles with 8 frames of overlap, and the HDR frames of a 121-frame fluid shot jumped 0.32 stops at frame 56, where the second tile starts (RTX PRO 6000, 2 Nov). The `hdr` workflow decodes in 128-frame tiles with 32 of overlap, as Lightricks' Tiled Fusion graph: the largest step fell to 0.07 stops, the SDR shot's own, and a shot of up to 128 frames is one tile.

**The viewer's 8-bit movies of an image sequence.** The second cause was in the viewer. It drew an image sequence's EXR frames where they had arrived and its 8-bit movie elsewhere, and that movie was in the model space, tone-mapped with the shot's peak (a white of 1.0 shows at about half its value at a peak of 15). Its 8-bit movies now hold log values (`logic.viewerSpace`: ACEScct when the config has it): the playback proxy (`proxy_space` of `ingest`), the review's viewer movie (output `view`, the optional link `review_view`, dropped for a video plate) and the SDR-to-HDR movie (output `movie`). While a source plays, it shows its EXR frames only once all of them are in (`logic.drawsDeep`, `holds`); paused, the precise frame shows. The review movie of the zip stays in the model space.

**Two passes in the wipe** (Ctrl+click on a finished Render step, Cmd+click on a Mac). The wipe's left side shows that pass against the pass on show on its right, both named, to find the step a fault comes from: a shot against its composite, a matte against the picture, a preview against the full size. A second video plays it beside the shot: a follower of the playhead (`followers` in `app.mjs`), synced by `tick` and `seek`. Paused, its frame comes at native size from the frames route, as the right side's does, and the plate shows on the left until it has one. A second Ctrl+click, Esc or F6 ends it, and the wipe goes back to how it was. The Color Inspector reads the side of the wipe its point is on (`inspector.wipeSide`): the plate, the pass compared or the pass on show, named in its Source row. The pixel route takes the plate's size (`of`), so a pass with fewer pixels, such as a preview, is read at the same place in its own pixels: 1.7.0 read the plate's pixel numbers there and failed.

**The X-ray** (W, free in OpenRV's `rvui.mu` and in the page), as PlateLock's: where the edits on show change the plate, tinted over the picture. `xray.xrayPlan` picks the mattes: the export's once Export has made one, else the tracking mattes of the size on show (the erase matte and the paint matte); a light edit changes every pixel, so it tints the whole frame. The tint is drawn on its own canvas, `#xray`, above the picture with its zoom and pan, so the inspector's final colour and the colour picker read the picture without it. Paused, each matte's frame comes from the frames route at 512 px (`XRAY_SIDE`), in any browser; playing, its movie plays as a follower of the playhead. Until every matte has the frame, the last tint stays.

**The viewer against OpenRV (viewer workstream, 2 Nov).** The colour tools are RV's own math, in `display.mjs` (`colorMatrix`, `displayUniforms`), read from OpenRV `0bd9675`: RV multiplies each tool on the left of one 4 x 4 matrix (invert, exposure, contrast as (1 + c) x - c / 2, hue as a sheared rotation about the grey axis that keeps Rec. 709 luma, saturation), and its shader applies gamma before that matrix. Contrast is 0 at rest, as RV's `color.contrast`. RV's invert matrix carries (1, 1, 1, 0) as its last row, so contrast after an invert scales its offset by r + g + b; the viewer keeps that, for RV's values. `ocio.py` asks OCIO for the GPU processor OpenRV asks for (`OPTIMIZATION_DEFAULT`), in GLSL ES 3.0 instead of RV's GLSL 1.3. `tests/test_rv_parity.py` holds the reference (RV's math, with PyOpenColorIO's CPU processor in place of RV's GPU one) and `tests/flows/viewer.py` reads the canvas for 12 pixels and every case.

**Reviewed against OpenRV (3 Nov).** OpenRV's `main` is still `0bd9675` (2 Nov, 14:31 EST). Read again line by line against `display.mjs` and `ocio.py`: `ColorIPNode.cpp` (gamma's exponent is 1 / gamma, applied first as `pow(max(x, 0), exponent)` in `ColorGamma.glsl`; then one matrix, each tool multiplied on the left: invert with its (1, 1, 1, 0) last row, exposure, contrast (1 + c) x - c / 2, hue iR * iZsh * Rz * Zsh * R, saturation with `Rec709FullRangeRGBToYUV8`'s first row, 0.2126001, 0.7151999, 0.0721999; offset, scale, CDL and the luminance LUT stay at rest in Paint a plate), `OCIOIPNode.cpp` (`getOptimizedGPUProcessor(OPTIMIZATION_DEFAULT)`, the channel flood after the display with the same weights) and `ocio_source_setup.py` (OCIOFile, RVColor, OCIOLook, OCIODisplay). No difference in values. Paint a plate's weights are 0.2126, 0.7152, 0.0722: 1e-7 apart, far below one code value. Adrien has no OpenRV, so the parity stands on this reading and on `tests/test_rv_parity.py` with the canvas readback (23 cases, 1 code value at most).

**The colour inspector** (`inspector.mjs`, F5, View > Color Inspector, as `toggleColorInspector` in `rvui.mu` and `inspector.mu`, with annotate mode's rules from `annotate_mode.mu`, OpenRV `0bd9675`). The inspector and the brush are active at once: a plain click paints; Shift+click samples a pixel and Shift+drag averages the pixels it passes (RV's `pointer-1--shift` binds, which annotate mode passes on). The box sits beside the sampled point with a marker on it, and dragging the box moves the point with it (RV's widget drag). The point lives in the plate's own pixels (from the top left) and every redraw reads it again (`refreshInspector` at the end of `render`, `renderFluid` and `applyView`), so the values follow the frame, the source, the pass on show, zoom and pan. The source values come at full precision and native size from `/paintaplate/pixel` (`routes.pixel`: an EXR's half floats as stored, a video's frame decoded with its own YUV matrix and range); the final colour is read from the canvas. It reads the file on show: the shot's EXR frames in their own space (`setShot`'s `framesSpace`), else its movie, whose codes it names as such, else the plate.

**The plate at its own size** (viewer workstream, 2 Nov). The canvas holds the plate at its native size, up to 4096 px on the long side (`NATIVE_SIDE`, the frames route's limit and the pipeline's movies'), and key 1 shows it 1:1 in device pixels (`display.oneToOne`), as RV's 1:1. Editing stays at the working size: strokes, edit previews and the brush draw through one scale (`inWork`), and `frameAt` returns working-size pixels. Paused, the frame on show comes from the frames route at native size and full precision, one frame per source (`sharpFrame`: the plate, and the shot's EXR frames or movie), so an EXR shows its half floats and a video its source frame, decoded on the server (`routes.video_frames`: planar YUV through the file's own matrix and range in float, from its samples at their bit depth). While a source plays, the movies and the 960 px cache stay. From 1:1, the canvas draws with `image-rendering: pixelated`, so a plate pixel shows as a square.

**Zoom and pan as OpenRV** (viewer workstream, 2 Nov). The bindings of `rvui.mu` (`0bd9675`): f fits, Ctrl+F fits the width (RV's Frame Width), 1 to 8 show N:1 and Shift+2 to Shift+8 show 1:N in device pixels (RV's Ctrl+2 to Ctrl+8; Chrome keeps Ctrl and Alt with a digit for its tabs), Ctrl+drag zooms about the press point with RV's `dragZoom` curve (to the right k + 15 m², to the left k - 0.75 m, m = |dx| / width x k x 2), Alt with both buttons zooms too, Alt+drag and the middle button pan, Shift locks the pan to one axis; the wheel steps frames, as in RV. The math is pure (`display.mjs`: `pixelScale`, `dragZoomScale`, `zoomAbout`, `lockAxis`, `pointIn`), and `frameAt` maps the pointer through the view's laid-out box, so a stroke lands under the pointer at every zoom.

**The wipe on a fluid shot.** With the keyframes open and a shot made, the wipe shows this frame's painted keyframe on the left, or black where the frame has none (no onion skins), against the shot on the right; the left label reads « Keyframe ».

**The colour tools while a source plays.** At rest a playing source shows its 8-bit movie until all its EXR frames are in. Once a colour tool moves, a source with EXR frames shows only those (`display.exactFrame`: the frame on show, else the nearest one in), as RV plays what it has decoded: four stops up, the 8-bit ACEScct movie of a fluid shot was 4 display levels off at the median and 24 at p99 in its dark background, with H.264's 8 px blocks.

**Models and licences** (`web/models.json`, `models.mjs`, Help > Models and licences). The registry holds every model file with the licence its Hugging Face repository states at the pinned revision, the original model's licence where a repackaged file differs, its source and its use; `tests/test_models.py` checks it against `get_models.py` and every workflow. The view lists the models behind the result on show, from the files the workflows that made it load (`workflowsFor`, `modelsBehind`), then every model.

**Passes on show.** The Render panel's finished rows with a movie (`logic.PASSES`, `passMovie`) and a First frame row: `choosePass` sets `S.pass`, the viewer shows that pass on every frame, and the pipeline's own `setShot` calls wait until `S.pass` is null again (a second click, Esc after the selection, or other edits). The clean plate pass keeps its own movie as `cleanRaw`. The tracking steps and the export show their matte: the `matte` and `export` workflows also save it as a grey movie (optional outputs, dropped when the page sends no prefix, as in the ComfyUI graph), drawn through the config's data colour space (`logic.dataSpace`, OCIO's isdata, such as Raw), so it shows its own values. A made fluid shot has its own rows, with its keyframes open or closed (`logic.fluidPasses`): Fluid: keyframes (the control video, an optional output of `fluid`), Fluid: shot, and for a 16-bit plate Fluid: SDR to HDR.

**Start and the fluid export.** With no plate open, boot opens a blank plate at the Blank tab's settings (`BLANK_AT_START`, `openBlank({ atStart })`), 16-bit when SDR to HDR is ready (`logic.defaultDepth`). A fluid shot with no edit on it exports itself (`fluidOnly`, `downloadFluid`): the download route's parts `hdr`, `plate` and `preview` of its folder (`logic.fluidRun`).

**Dropped links** (`drop_link`, `dropLink`) also remove the nodes that only fed what went, so a filled workflow holds no node that feeds nothing.

**Deliver** (`#deliver`, `deliverUI`): the panel of passes that run after the full-size composite, each on or off, in the side panel beside Render. Its first pass is the bit-depth pass: the deliberate SDR to HDR of a plate whose format holds nothing above 1.0 (`S.deliver.hdr`), confirmed first, delivered as an EXR sequence (`logic.exrResult`). The other passes (upscale, alpha, depth, normals, IDs) come next, each model in `web/models.json`.

**The workflows a render ran** (`r.flows`). Each finished or reused step adds its workflows to its render's record (`logic.STEP_FLOWS`: a full-size clean plate pass runs `clean` and `cleanup`). Models and licences and an export's `MODELS.md` name the models behind the result from that record, the edits' own workflows (the prompt writer and Klein, SAM's object search for an erase) and a fluid shot's (`logic.resultFlows`, `modelsOnShow`), so a step that never ran, such as SDR to HDR on an SDR plate, lists no model.

**New content at the plate's bit depth** (`logic.plateDepth`, read from the plate's pixel format). The frames a shot and the clean plate pass pass through on their way to the export are 8-bit PNG for an 8-bit plate, 16-bit PNG for a 10, 12 or 16-bit plate (10-bit and 12-bit video, ProRes among them, 16-bit PNG and TIFF, 10-bit DPX), and half-float EXR for a plate of floats, EXR or a float TIFF or DPX (Save Frames' `png`, `png16` and `exr`, the `frames_format` slot of `clean`, `cleanup` and `shot`). The export already writes each plate at its own depth (Save Plate), so the new content keeps more than 256 levels on every plate deeper than 8 bits. SDR to HDR runs on its own for a plate that holds values above 1.0; `S.deliver` holds Deliver's passes for the plate (`hdr`, the deliberate conversion), the fluid shot under the edits keeps them, and scenes save them (version 6; a version-5 scene's switch, on, becomes Deliver's `hdr`).

**Live previews and stopping.** Live Preview patches every LTX pass (preview and full size, the clean plate pass's two stages, SDR to HDR, the fluid shot): the first preview at step 1, then every other step, each naming its step and the pass's steps from the sampler's `sample_sigmas` (the page shows « step 3 of 8 », and the stage of the two-stage clean plate pass). At full size the latent is averaged first so the tiny decoder works at about twice the preview's size, and the SDR-to-HDR pass's ACEScct codes show through `mathops.acescct_preview` (Reinhard, then the sRGB curve). `showLive` draws in the frame until a shot exists for the edits on show, then fills the inset `#live-inset`. Esc follows `logic.escapeAction`: `stopGenerating` sets `S.halted`, cancels the render's and the fluid's jobs and keeps every finished step; `idle` waits, and Enter clears it. Stop, beside Generate while anything generates, does what Esc does. Cancel on the opening screen, or Esc, stops a plate that is opening (`cancelOpen`); Close plate stops every job, resets the frame caches and empties the page (`closePlate`), and ComfyUI keeps its models.

**The way back from the model space.** Out of `@model`, the composite undoes core's tone mapping with the plate's peak (`ocio.undo_tone`; the plate's conversion into the model space reads the plate's peak once and gives it as its second output, `peak`; the shot's return and Relight Transfer take it as a number, and `peak_of` stays for a first frame converted alone, in `ingest`), so new content comes back at the plate's levels. At a peak of 7.4, a grey of 0.18 came back 0.23 stops low and a white of 1.0 came back 0.97 stops low before 1.11.13; the error is now 0.00015 stops at most. Relight Transfer measures the light the same way (`ocio.out_of_model`, its input `peak_of`). A plate whose peak is at or under 1.0 gives the same bytes as before. A saturated colour above 1.0 keeps its luminance, not its saturation. The preview stays in the model space. Not measured on a GPU yet: `tests/hdr_plate.py` makes an HDR plate from a movie and measures an edit's level against the plate at the matte's seam.

## 7. The fluid shot

1. **A blank plate.** With no plate open, the page opens one at start, at the tab's settings (`?blank=0` starts empty). In the Open dialog, the Blank plate tab posts to `/paintaplate/blank`, which writes a black ProRes 4444 canvas in `input/paintaplate/blank`, once per size. Sides are multiples of 64 up to 1920; lengths are 8k + 1 frames, from 9 to 321; frame rates are 24, 25 or 50 fps. Two more options of the address serve the tests: `?seed=<n>` starts every new edit and every new fluid shot from seed n, so a run makes the same pictures again, and `?index=0` leaves the job index alone, so every job runs and is timed (`logic.askedSeed`, `logic.plateIdentity`).
2. **Keyframes.** The brush paints on frame 0, on the last frame, and on the 8k + 1 frames between (`snapKey`). Diamonds on the timeline drag between free slots; Ctrl+C and Ctrl+V copy a keyframe, Delete removes it, and onion skins show the keyframes around the playhead.
3. **Generate** (Enter, `generateFluid`). The `fluid` workflow runs one LTX 2.5 pass. Keyframe Video builds the control video (black frames with each keyframe at its frame). `LTXICLoRALoaderModelOnly` reads the LoRA's downscale factor and hands it to `LTXAddVideoICLoRAGuide`. The sampler is `euler_ancestral` with the 8 distilled sigmas at CFG 1, and the prompt is `ainvfxfluid, ` followed by your words (`fluidPrompt`).
4. **The first edit.** Once made, the fluid shot is the plate the next edits are painted on: History shows it as edit 1, Fluid, under the others. Its pencil brings the keyframes and words back, its eye bypasses it (the blank plate under the edits), and it can try another seed or be removed. The edits on it keep one result per plate they were made on (`recordOf`, `base`).
5. **Scenes.** Save scene keeps the scene on this ComfyUI (`/paintaplate/scenes`, in `output/paintaplate/scenes`): the plate and its file colour space, the OCIO config, display and view, the fluid shot's keyframes, words and seed, and every edit with its strokes as drawn. Open plate > Scenes opens it again, or downloads it. Strokes are saved in pixels of the working size the scene names, and drawn in one pass before any image is made from them: the same scene makes the same images, so the same jobs. A fluid scene keeps its blank plate in the model space, as Open plate makes it; its fluid shot, and for a 16-bit plate its SDR to HDR, come back from the job index, so the EXR frames under the edits keep their files and every job on them is found again. Scenes of versions 1 and 2 still open, with the colour space read from the file.

Without `ainvfx-fluid.safetensors`, fluid shots switch off and the rest of the app works (`boot` sets `S.fluidReady`).

## 8. The Open dialog

Open plate has one tab per source: **ComfyUI files**, **Upload**, **Scenes** and **Blank plate**. ComfyUI files browses the input and output folders and their subfolders through `/paintaplate/browse`, which reads names, sizes and times only (`plateio.scan_folder`): numbered images are grouped into sequences named by frame pattern, an image alone is counted but not listed, and videos, animated images and saved scenes appear as they are. The page sorts and filters the list (`logic.browseItems`), draws `BROWSE_PAGE` items at a time as the list scrolls, and asks for a thumbnail only when it shows; the server makes at most four thumbnails at once and keeps each one in ComfyUI's temp folder. One click reads the item's details and guessed colour space (`/paintaplate/stat`); a double click opens it. At the input or output root, the route also returns the newest plates of the folders below (`routes.plates_below`: 60 at most, from at most 400 folders, Paint a plate's own folders left out), each listed with its folder.

The saved file also holds the page's API graph, in `extra.paintaplate.prompt`: `tests/graph_live.py` compares it with what ComfyUI's own editor sends. Its images sit at the top of ComfyUI's input folder, named after the plate, the edit, what each holds and its hash (`logic.graphImageName`): ComfyUI's image loaders list only the files there, and the editor marks any other file as missing. The graph's own note lists every file it needs. |

## 14. Known limits

These come from GPU tests on an RTX PRO 6000 in October 2026.

- An addition painted across a foreground object breaks up mid-shot: a scooter painted over a fountain's rim did. Paint additions in open space.
- An erased head comes back as a head. Paint the new head over the old one instead.
- An explosion painted on a moving car drives off with it. Clean the car first.
- A name finds that object only: « floodlight » found the lamp, and « floodlight pole » the pole.
- The paint matte takes what the shot changed within 1/16 of the width of the object's region. An effect that jumps further than that in one frame is not caught.
- After frames where the object is not seen, the matte searches up to 4 × 1/16 of the width around its last place: an object that comes back further away stays out. For an object that stands still in the scene, the search moves with the plate's background and does not grow while the plate covers the object's place. The plate is asked about every place it has shown, up to one frame's width on each side of the first frame.
- In a fluid shot, the painted colours win over the words: paint a dusk sky in dusk colours.
- A video plate's review is 8-bit H.264 at crf 12, the same class as an 8-bit plate; a 10-bit video plate's review loses its extra bits in the viewer (the export keeps them). An image sequence's review is read at 960 px on the long side for playback.
- Model inputs come from the plate in the model space: values above 1.0 are tone-mapped into it, and edited pixels come back within 0 to 1 of it, as with core's conversion.

**The light brush and its light plan.** Light strokes are soft dabs at a fixed spacing (`logic.dabsAlong`), each stroke adding at most `LIGHT.flow` of its colour (`dabFlow`); shade strokes (a dark colour) go to their own layer, `d.shade`. A relight gives Klein two references: the frame as it is, and the light plan (`lightPlan`), the light's strokes alone on grey (RGB 58, `logic.PLAN_GREY`) with the shade strokes in black, drawn solid, on the `edit` workflow's optional second reference (`edit_plan`). Its request is the page's own (`logic.lightPlanCaption`), so a light needs no prompt writer. Klein ignores a painted shadow, so the shade strokes go to Relight Transfer as a soft white mask (`shadeMask`), which darkens the frame there in linear light (`mathops.shade_frame`, density 0.7, optional link `relight_shade`). The ComfyUI graph uploads the same plan and shade.

Found on 11 November 2026, on the 16 GB reference laptop (62.7 GB of RAM):

- Opening a plate holds it once, padding included. Load Plate decodes a movie or an image sequence with the pack's own decoder (`plateio.decode_video`, `plateio.decode_frames`), which writes each frame into its place and makes core's pictures. Its array holds what the file's header says, up to `max_frames`, and grows or shrinks in place when the file holds another count. Core's decoder held the plate twice (its list of frames, then their stack), and the figures that follow were measured with it. On a pod's CPU ComfyUI (11 November), a 1920 x 1080 plate of 121 frames took 6.2 GB at its peak where 1.11.8 took 17.4 GB, and ComfyUI kept 5.1 GB after it where it kept 17.1 GB; a 3840 x 2160 plate took 23.1 GB where it took 65.9 GB. One float32 copy of the 1920 x 1080 plate is 2.80 GB. The laptop measured 23.5 GB and 17.9 GB at 1.11.8, and has not run this open yet. `tests/open_probe.py` names the node that takes it, and its `--same` says whether two opens made the same pictures. Save Movie converts at most twice its workers ahead of x264 and makes its 8-bit frames in strips of 64 lines (`plateio.core_uint8`): in the sandbox, 121 frames at 1280 x 720 took 233 MB above the level before, where they took 628 MB. Neither change is measured on the laptop yet.
- A 3840 x 2160 plate of 121 frames at 50 fps ran paint, erase and light on a 96 GB card with 188 GB of RAM (a pod, 11 November, 1.11.8). ComfyUI held up to 121 GB of RAM for the paint, 117 GB for the erase and 164 GB for the light, each in the full-size composite (`review`), then 91 to 138 GB in the export. One float32 copy of that plate is 11.2 GB.
- The page sets no limit on a plate's frames: every workflow gets the plate's own count. 121 frames is what is tested; a blank plate takes 9 to 321.
- On the 16 GB laptop, under the small memory profile, the cow case took 785 s at 1.11.8 (11 November): 577 s of it in the full-size shot, which took 152 s with the same settings on a 96 GB card.
- **Numbers too far apart are not frames.** A group of numbered images is a frame sequence when at least one of every 100 numbers between its first and its last exists (`plateio.SPARSEST`). Sparser, the numbers count files: one frame per file. ComfyUI's mask editor names its files by the millisecond (`clipspace-mask-1791816680123.png`): until 1.11.4 the Open dialog's thumbnail of such a group took all of ComfyUI's memory.
- **The cow behind the horse.** A painted object that stands still in the scene and passes behind something the plate holds leaves the paint matte while it is hidden and comes back into it where it comes out (`mathops.follow_matte`, from frame 8). When the object in front stood next to it on frame 0, it comes back 3 frames after it comes out in the test scene (6 before 1.11.13): its place's first look is also read inside the place, so what stood beside it is no part of it. A few pixels of what stands in front can enter the matte where the two touch. A piece of a still object that leaves the object's place, with what stands in front or alone, is left out, and the plate shows there: LTX can draw a painted cow walking away with the horse. An object that stands still for its first 8 frames and then moves by itself is lost the same way. An object that moves in the scene over its first 8 frames, or that is covered within them, is followed as before. First run on a GPU on 12 November (the laptop, 1.11.12). The matte shrank with the cow as the horse covered it, was empty while the cow was hidden, and left out the cow's head that the preview gave the horse. After the horse passed, LTX drew the cow at its place again on 4 of 5 recordings, behind the fence, and the matte took it back with no mask from SAM, leaving out the fence rail in front of it (from frame 86 on the laptop's full-size pass). On the fifth, LTX walked the cow off with the horse, and the matte ends empty. Replayed on the pod's three recordings of 12 November too: the piece beside the horse's ear is out on every frame, and the cow drawn moving with the horse is out from the frame it has left the cow's place and its margin. `PAINTAPLATE_RECORD=<folder>` in ComfyUI's environment makes Follow Matte write what it was given (`mathops.record`), and `mathops.follow_matte(**mathops.replay(file))` runs it again without a GPU. A replay runs on 8-bit copies of the frames, so its counts can differ from the live run's by a few frames.
- **The paint zone.** SAM 3.1, prompted with the paint zone, returns the zone on its first 10 to 13 frames. On those frames the matte of an object that stands still is its place of frame 0, moved with the background: 1.1 to 1.3 times the cow on five recordings, where it held 3.9 to 5.4 times. LTX's cow can drift a few pixels on those frames; the matte then covers 76 to 90% of it, and the composite's growth covers the rest. An object that moves inside its paint zone over its first 8 frames reads as standing still: the matte keeps to its place of frame 0, and loses it from frame 8. Replayed on five recordings, and not run on a GPU yet.
- **A soft plate.** `plate_move` reads a pan of 1 px per frame, at 128 px of width, as 0.33 px on a texture blurred at 2 px, 0.90 px at 1.5 px and 0.99 px at 0.7 px: its 25 px tiles are small for a soft texture (`tests/test_plate_soft.py` pins these readings). The horse plate reads well; a misty or defocused plate may not.
- An erased object that passes behind something is back in the matte when SAM 3.1 finds it again: until then it shows. A thin piece of it beside what stands in front can come back one frame late. On the laptop (12 November, 1.11.12) the matte of `horse_erase_barn` fell on every frame from 20 to 34, was empty on 58 to 100 while the horse hid the barn, and came back on frame 101. Once it is known to stand still, an erased object's place of frame 0, moved with the background, is in the matte wherever the plate shows it thick, seen by SAM or not: replayed on that recording, the barn comes back into the matte on frame 98. Its first 18 to 47 px in view, on frames 95 to 97, are too thin to enter the matte, and show.
- **The erase on a 16 GB card.** The second stage of the full-size clean plate pass (`cleanup`) held the shot nine times at full size before LTX started, about 25 GB for 121 frames at 1920 x 1088 by count. On the laptop its memory rose from 32.0 GB to 48.5 GB in 17 s, and ComfyUI stopped there under a cap of 52 GB of RAM (12 November, 1.11.9). Since 1.11.10 Composite Frames makes that start one frame at a time. On the laptop the stage was then posted at 28.5 GB, held 31.8 GB before LTX loaded and 38.3 GB at its peak, and the case `horse_erase` ran to its end in 359 s (12 November).
- **An erase with no words.** The prompt writer gets a box cut to the object (`logic.coreBox`, 1.11.14). On the laptop (13 November, 1.11.14) it named the barn, and the barn went on the first frame and in the whole shot (`horse_erase`, 344 s). A stroke on the tree, whose box takes in the barn's roof, was still named the barn, and the page asked for the tree's name. The page now leaves the barn out of the writer's box and asks the writer again (`logic.boxWithout`): on SAM 3.1's masks of that frame the cut box holds 1% of barn and keeps 87% of the tree. Not run on a GPU yet. Before 1.11.14 the writer named the horse where the stroke lay on that barn, and the erase left the barn in the shot (12 November, 1.11.10).
- The check of an erase (`logic.eraseCheck`) reads mean colours on cells of 4 pixels at the edit preview's size. The object reads as still there when under 30% of it moved by more than 24 levels, or when its edges held above 0.85. On 19 real first frames of `horse.mp4` (13 November) a kept object reads 0 to 3% and 0.91 to 0.98, and a removed one 53 to 97% and -0.07 to 0.76: the margin on the edges is thin. The check can be wrong, so the page asks « Render anyway » when it holds an erase back. It looks inside the object's mask only, so it does not see a neighbour that Klein removed with the object; `tests/erase_probe.py` measures the band that the edit reaches outside the mask.
- **A pale band where an erased object was.** The clean plate pass erases the tracker's own mask, and the composite pastes Follow Matte's matte, which also holds the object's place of frame 0 where SAM 3.1 lost it. Where the two differ, the composite shows the plate's object, softened by LTX.
- x264 does not always make the same movie from the same frames: on a CPU with AVX-512, 17 frames of 960 x 540 at crf 12 gave up to 7 different movies in 12 (12 November). The pictures are equal in quality. Tests compare movies written without loss, or frames.
- **Time estimates learn.** The Render panel's estimates come from what each step took the last time on this machine (`paintaplate.times` in the browser's storage, per step, size, frame count and memory profile), else from `logic.stepGuess`: the 96 GB card's reference scaled to the plate and, on a 16 GB card, a lead in seconds per model family plus a factor per step (`logic.SLOWER`), measured on the laptop at 1.11.12 on one plate size (1920 x 1080, 121 frames). There, 30 of the 31 measured steps are within 25% of their announcement. Other sizes are not measured.

## 15. Memory: the card, the frame caches and the trace

**The memory profile.** At page open, `warmAll` reads the card's VRAM and RAM from ComfyUI's `/system_stats` and sets `S.memoryProfile`: `{ name, why, does, warm, slots }` (`logic.memoryProfile`). The log says it in one message: the profile and the card, then what the page does on it.

| Profile | VRAM | What loads at start | LTX's tiles |
| --- | --- | --- | --- |
| `small` | Under 24 GB (`MEMORY_FROM.medium`, 24e9 bytes: a 16 GB card reports about 17.2e9) | Nothing. Each model loads when an action needs it, so the prompt writer, Klein and LTX take turns | 256 px, and the guide is encoded in tiles |
| `medium` | From 24 GB (a 24 GB card reports about 25.7e9) | The edit models; LTX with the first shot | 512 px |
| `large` | From 60 GB (`MEMORY_FROM.large`) | Every model, and they stay loaded | 512 px |

One set of workflows serves every profile: `slots` fills the `tile` and `guide_tiled` slots, and `warm` names the workflows `warmAll` posts. `?memory=small` (or `medium`, `large`) in the address, or the `paintaplate.memory` setting, asks for a profile in place of the card's. The borders move with measurements: `tests/gpu_matrix.py` writes each case's peak VRAM and RAM. On a 96 GB card, asking for `small` cost 73 s on a 258 s case (11 November): the time goes to loading each family of models again after a free. The 256 px tiles and the tiled guide cost 11 s at most.

**The frame caches.** `FrameCache` (decoded frames) and `DeepFrames` (an image sequence's half floats) share one budget, set in View > Cache memory and kept in `localStorage` as `paintaplate.cache`. It is Auto by default, and `?cache=<MB>` sets it for a test. `planCaches` gives each cache of the sources on show its share and its frame size, again whenever the budget, the frame's size, the sources or the in and out points change (`frames.cachePlan`).

**Playback from memory.** Once every frame between the in and out points is in memory for each source the picture draws (`memoryReady`), playback runs on a clock, from memory. Until then it follows the videos. `S.memory` is that path: `true` from memory, `false` from the videos, `null` when nothing plays. `?stats=1`, or View > Playback statistics, writes one log line for each stretch played (`PlayStats`).

**The trace.** With `PAINTAPLATE_TRACE=1` in ComfyUI's environment, a middleware in `routes.py` (`trace`) writes one line when a request starts and one when it ends: its method and address, the seconds, and the memory the process holds. `TESTING.md` says how to read it.
