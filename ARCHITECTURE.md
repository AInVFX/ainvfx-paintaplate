# AInVFX PaintAPlate: architecture

This document explains what PaintAPlate does, how it is built and where each part lives, for anyone who maintains the code. It describes version 0.4.13. `TESTING.md` covers the tests.

## 1. What PaintAPlate does

A **plate** is the source footage of a shot: a video file (MP4, MOV, MKV, MXF) or a folder of EXR, PNG, TIFF or DPX frames. You paint on the plate's first frame, and the change carries through the whole shot. There are three tools:

- **Paint** adds something new where you paint, from your words: a fire, a boat, a lamp.
- **Erase** removes an object. With **Whole object** on (the default), SAM 3.1 finds the whole object under the strokes, by its name when you type one.
- **Light** relights the scene from where you paint, in the colour of the brush.

Generate (the button at the end of the prompt bar, or Enter) starts an edit and everything after it. FLUX 3 Image Klein makes the edit on the first frame. The shot then renders by itself: LTX 2.5 carries the edits through every frame, SAM 3.1 tracks the changed areas, Follow Matte keeps every generated element inside the matte, and the result is composited onto the plate. Painting a new edit lets a render go on; changing the edit being generated stops it. Generate never makes a result twice: an edit whose strokes, words, seed and Whole object switch have not changed keeps its result. The export keeps the plate's own format: file type or codec, bit depth, frame numbers, colour tags, timecode, audio and EXR layers. Every pixel outside the edits stays the source pixel.

A **fluid shot** starts from a blank plate instead. You paint flat colour keyframes: light grey for smoke, white for steam, orange and yellow for fire, and optional flat zones for sky and ground. AInVFX's ainvfx-fluid IC-LoRA turns them into smoke, steam or fire in one LTX 2.5 pass. The result then opens as a normal plate, ready for every edit.

## 2. Words used here and in the code

| Word | Meaning |
| --- | --- |
| Plate | The source footage of a shot. |
| First frame | Frame 0 of the plate, where every edit is painted. In the code, `S.original` is the plate's first frame, and `S.hero` is the first frame with every active edit stacked on it. |
| Edit | One change painted on the first frame: its tool (paint, erase or light), its strokes, its words and its seed. The History panel lists the edits, numbered from 1 at the bottom. |
| Draft | The edit being drawn, before Generate (`S.draft`). |
| Current edit | The edit that new strokes, new words and the Whole object switch change: the edit just started, or the one picked in History (`S.selected`). The Editing tag in the prompt bar names it. |
| New edit | The action that closes the current edit, so the next strokes start a separate one: the N key, the button at the end of the prompt bar, or the right-click Edit menu. Picking another tool does the same. |
| Generate | The button at the end of the prompt bar, or Enter: it starts the draft or the changed current edit, then the render. Pressed with nothing changed, it runs nothing. Ctrl+Enter tries another seed. |
| Patch | The result of an edit: the new pixels of the first frame, as an RGBA image. |
| Pass | One run of a model. A Klein edit runs a quick pass at 768 px, then a full-size pass. |
| Working size | The size edits are made at: the plate's size, at most 1920 px on the long side, in multiples of 32. |
| Preview size | The size of the background render you watch. Fast (640 px on the long side) is the default; the menu offers other sizes computed from the plate, and Full. |
| Matte | A black and white mask per frame: where an edit changed the shot. |
| Erase pass | The plate with every erased object removed in every frame (the clean plate), made by LTX 2.5 with Lightricks' in-outpainting IC-LoRA. Workflow `clean`; at full size, in Lightricks' two stages: `clean` at half the working size, then `cleanup`. |
| Shot | The plate regenerated by LTX 2.5 with WepeNerd's Ripple IC-LoRA, from the edited first frame. It carries paint and light. Workflow `shot`. |
| Composite | The shot's new pixels inside the mattes, over the plate's own pixels everywhere else. |
| IC-LoRA | A LoRA for LTX that reads a reference video next to the prompt (an in-context LoRA). |
| Prompt writer | FLUX 3 Image Klein's own prompt upsampler (Qwen 3.5 9B). It writes each edit's caption in Black Forest Labs' format. |
| Workflow | A ComfyUI graph in API format, in `web/workflows`. The page runs every step of its work as one. |
| Slot | A named input of a workflow that the page fills before it posts it: a path, a seed, a caption. |
| Job kind | The group a posted workflow belongs to: `edit`, `snap`, `prefetch`, `warm`, `fluid`, and the background kinds `clean`, `shot`, `matte`, `comp` and `export`. A cancel stops jobs by kind. |

## 4. Design rules

These rules keep the code small and easy to change. Follow them in every change.

1. **All GPU work is a ComfyUI workflow.** The page loads a workflow file, fills its slots and posts it. The 10 PaintAPlate nodes only do what core ComfyUI cannot. So the app runs on any ComfyUI, and a Comfy API deployment stays possible.
2. **Workflows are generated.** `tools/build_workflows.py` writes `web/workflows`. Nobody edits the JSON by hand: a test fails when the files and the generator disagree.
3. **Each workflow describes itself.** In each node's `_meta`, `slots` maps the node's inputs to slot names, `output` names an output the page reads, and `progress` marks the node whose progress bar stands for the whole workflow.
4. **Optional links.** Some links exist only when the page has something to send: a matte to composite with, words to search by, a relit frame. When their slots stay empty, the page drops the link and every node that fed it. The rule is written twice, as `OPTIONAL` in `logic.mjs` and in `build_workflows.py`, and a test keeps the two equal.
5. **Pure code is tested without heavy dependencies.** `plateio.py` and `mathops.py` need neither torch nor ComfyUI. `logic.mjs`, `graph.mjs` and `frames.mjs` run in Node. `nodes.py` only converts tensors and calls them; `routes.py` is plain functions plus `setup()`.
6. **One edit at a time.** A stroke goes to the draft, else to the current edit if it has the same tool, else to a new edit (`strokeTarget` in `logic.mjs`). Another tool, or New edit, closes the current edit (`toolEndsEdit`). Undo keeps the current edit while it exists.
7. **Nothing made is lost, and nothing is made twice.** Changing the edit being generated (strokes, words, the switch) stops its Klein pass. No render stops for that, nor for a bypass, an undo, a removal or a new edit: renders go on, and what they make stays. Each run of an edit carries a token, and a run whose token is stale stops. Results are kept per set of edits and per preview size (`S.renders`, keyed by `S.heroKey`), so going back to an earlier state plays at once. What the erases make (their matte and their erase passes) is kept per set of erases (`S.erases`): a render with the same erases, such as a paint added over them or removed, uses it again. Every finished job is also recorded in the job index on disk (`routes.py`, `output/paintaplate/jobs`), by the hash of its workflow file, the plate (path, size and time) and its values. A job with the same hash takes those files back instead of running, in this session or a later one on the same machine; images are uploaded under the hash of their content, so their names match from one session to the next.
8. **Previews may trade quality for speed. The export never does.**
9. **Paths stay inside ComfyUI.** Every path from the page resolves under ComfyUI's input or output folder, and links are refused. Absolute plate paths need `PAINTAPLATE_ALLOW_ABSOLUTE=1`.
10. **One home per value.** Sizes, delays and budgets: the tuning block at the top of `app.mjs`. Model files: the constants at the top of `build_workflows.py`. Tested ComfyUI and ComfyUI-LTXVideo commits: `tools/pins.sh`. Model revisions: `rev()` in `tools/pod_setup.sh`.
11. **A log line for every wait.** Each step a person waits for writes one line in the page's log: what runs, with which values, and how long it took.

## 5. The life of an edit

1. **Open a plate** (`openPlate`). The `ingest` workflow decodes the plate once. It saves the first frame (at most 1920 px on the long side), a 960 px H.264 playback video and the plate spec (codec, size, frame rate, frame count, colour space). The page then sets its sizes: the working size, 768 px for quick passes, 960 px for tracking (640 px for erase mattes) and the preview size.
2. **Paint.** Each edit draws on two canvases: `paint` (what Klein sees, for a paint) and `mask` (where the edit may act). `strokeTarget` decides which edit a stroke joins. I (or the pipette by the swatches) picks a colour from the frame for the brush (`pickedColor`).
3. **Prepare while the strokes rest** (`prepareSoon`, then `prefetch` and `prepare`). `takeInputs` reads the words and the Whole object switch into the edit. For an erase with Whole object, the `snap` workflow asks SAM 3.1 for the object by name and from up to five stroke points, and `pickObjects` keeps the right masks. Then the `prompt` workflow asks the prompt writer for a caption, and `reconcile` puts the page's boxes back into it. An erase sends one locked box per painted part (`paintBoxes`), and a caption that removes something the paint does not cover gives way to the page's own (`erasesPaint`). A new stroke cancels this work.
4. **Run the edit** (`launch`, then `generate`) when you press Generate (Enter). An edit whose strokes, words, seed and switch match a result it already made takes that result back (`reuse`, up to `RESULTS_KEPT` results per edit), so pressing Generate twice runs nothing twice. Ctrl+Enter tries another seed. The `edit` workflow runs twice: a quick pass at 768 px (16 steps, denoise 1, with live previews inside the strokes), then a full-size pass from that result (8 steps, denoise 0.35). The result is the edit's patch. An erase's fill is levelled with the background around it first (`levelFill`): Klein can leave a faint, pale shape of the removed object, which LTX then animates. The edit stays the current edit. For an erase, the full pass ends in Level Fill, which levels Klein's fill with the background around it: left in, a pale imprint of the removed object became smoke in the erase pass. The `edit` workflow saves its outputs to the output folder, so the job index finds them later.
5. **Stack the first frame** (`recompose`). Active patches stack on `S.original` to make `S.hero`. When an edit changes, the edits above it run again only if they depend on it (`dependsOnChange`: one of the two is a light, or their footprints overlap on a 96-cell grid).
6. **Render** (`idle`, then `pipeline`), from the render queue. Every set of edits shown is a render (`want`), made from a copy of its edits (`freeze`). One step runs at a time (`pickRender`, `logic.nextRender`): every preview before any full size, every full size before any export, the set on show first, then the most recently shown, for the last `RENDERS_WANTED` sets. A render gives way between steps (`YIELD`) and resumes later where it stopped. Nothing stops a step but Generate, which stops a full-size or export step in its first half (`preempt`, `logic.stopsForEdit`); that step runs again later. `plan` skips the steps an edit set does not need:
   - `matte` at 640 px tracks each erased object (SAM 3.1, then Follow Matte: one matte per frame even when SAM returns none, the last matte where SAM loses the object, and no other object SAM finds by itself);
   - `clean` makes the erase pass: each erased area as blocks of LTX's 32 px grid, grown by one block, and a prompt that describes the scene as it stays (`erasePrompt`), never the erased object;
   - `shot` regenerates the shot over the clean plate (or over the plate when nothing is erased), for paint and light;
   - `matte` tracks each painted area, and Follow Matte adds every pixel the shot changed near it, compared with the plate the shot was made over: an element SAM drops stays in the composite, and other objects SAM finds by itself stay out. The paint matte starts from the pixels the edits changed on the first frame (`changedMask`), not from the whole paint zone;
   - `comp` makes the composite at the preview size.

   Then the same steps run at full size, followed by `export`. At full size the erase pass runs in Lightricks' two stages: `clean` at half the working size (the preview's own pass when the preview is that size), then `cleanup`, 2 steps at full size. These steps run when background export is on (the default) or after you press Export. The viewer plays the full-size shot as soon as it is made, then the export: the preview size can lose an effect that the full size keeps.
7. **Export.** Save Plate writes the result in the plate's format, plus the matte frames and a full-size H.264 review movie. The route `/paintaplate/download` zips the parts ticked in the Export dialog.

On cards with 24 GB or more, preview passes show a live preview: every second step, the Live Preview node decodes the frames LTX predicts into a looping WebP.

## 6. The fluid shot

1. **A blank plate.** In the Open dialog, the blank plate form posts to `/paintaplate/blank`, which writes a black ProRes 4444 canvas in `input/paintaplate/blank`, once per size. Sides are multiples of 64 up to 1920; lengths are 8k + 1 frames, from 9 to 321; frame rates are 24, 25 or 50 fps.
2. **Keyframes.** The brush paints on frame 0, on the last frame, and on the 8k + 1 frames between (`snapKey`). Diamonds on the timeline drag between free slots; Ctrl+C and Ctrl+V copy a keyframe, Delete removes it, and onion skins show the keyframes around the playhead.
3. **Generate** (Enter, `generateFluid`). The `fluid` workflow runs one LTX 2.5 pass. Keyframe Video builds the control video (black frames with each keyframe at its frame). `LTXICLoRALoaderModelOnly` reads the LoRA's downscale factor and hands it to `LTXAddVideoICLoRAGuide`. The sampler is `euler_ancestral` with the 8 distilled sigmas at CFG 1, and the prompt is `ainvfxfluid, ` followed by your words (`fluidPrompt`).
4. **The first edit.** Once made, the fluid shot is the plate the next edits are painted on: History shows it as edit 1, Fluid, under the others. Its pencil brings the keyframes and words back (the edits above stay until a new shot is made), its eye bypasses it (the blank plate under the edits), and it can try another seed or be removed. Another tool closes the keyframes. The edits on it keep one result per plate they were made on (`recordOf`, `base`), so bypassing and turning it back on takes their results back.

Without `ainvfx-fluid.safetensors`, fluid shots switch off and the rest of the app works (`boot` sets `S.fluidReady`).

### The 10 nodes, in `nodes.py`

| Node | What it does | Used by |
| --- | --- | --- |
| Load Plate | A video or a frame folder at full precision: frames, alpha, spec, frame rate, frame count; optional 8k + 1 padding | most workflows |
| Save Plate | Writes the plate's format, with the exact source pixels wherever nothing changed ; for a video plate, the untouched pixels are its own YUV samples, with no RGB round trip | `export`, `fluid` |
| Fit to Plate | Resizes, aligns, matches the colour at the edge, adds grain, steadies the soft mask | `comp`, `export` |

| Relight Transfer | The new light from the regenerated frame: its brightness with sharp edges, its colour smooth, and no channel divided by almost no light (`light_ratio`); the texture and highlights from the plate; sRGB inputs are decoded and the result encoded here, frame by frame in parallel (`plate_space`, `shot_space`) | `edit`, `comp`, `export` |
| Save Frames | Saves a batch as numbered PNG frames, named as core Save Image names them, several frames at once (core took 35.3 s for a 1080p shot) | `clean`, `cleanup`, `shot`, `matte`, `export` |
| Save Movie | Saves a batch as the H.264 movie the page plays, as core Save Video makes it (crf 18, BT.709, limited range), the frames converted several at once and x264 at preset veryfast (core took 8.3 s for a 1080p shot) | `ingest`, `clean`, `cleanup`, `shot`, `comp`, `export` |
| Follow Matte | One matte per frame from SAM's track, following the object's own region, which starts where the edit changed the first frame (for paint) or at the first-frame mask, and moves by at most 1/16 of the width per frame: SAM's mask further away stays out, even joined to the object by a thin line, the last matte holds where the object is not seen (the first-frame mask when SAM returns none), and for paint every pixel the shot changed near the object joins | `matte` |
| Level Fill | An erase's fill levelled with the background it continues: where the fill is flat and a few levels off the background around it, the difference goes, low frequencies only; edges, revealed objects and textured fills stay as they are. Off, it passes the image through | `edit` |
| Live Preview | A sampler hook: a tiny-decoder WebP every N steps; it switches itself off on any error | `clean`, `shot`, `fluid` |
| Keyframe Video | Black frames with each keyframe at its frame | `fluid` |

## 9. Inside `app.mjs`

**The tuning block** at the top holds every size, delay and budget: `IDLE_MS` (0.3 s between the last change and the render), `RESULTS_KEPT`, `RENDERS_WANTED` (the sets of edits whose renders go on in the background), `FOLLOW` (how far and how much a change joins the paint matte), `PREFETCH_MS`, `QUICK` and `FULL` (the two Klein passes), `CACHE_MB`, `WORK_SIDE`, `EDIT_SIDE`, `TRACK_SIDE`, `ERASE_TRACK_SIDE`, `LIVE`, `WARM_ALL_VRAM`, `PREVIEW_CAP`, `UNDO_MAX`, `PAINT_GRID`, `EDIT_GROW`, `PAINT_ZONE`, `ZONE_SOFT`, `WIPE_GRAB`, `COMPOSITE_GROW` and `COMPOSITE_FEATHER`. For tests, the URL options `?refine=`, `?cache=` and `?shot=` override some of them.

**The state** is one object, `S`: the plate, the edits (`S.edits`), the draft, the current edit (`S.selected`), the edit being generated (`S.running`), the undo and redo stacks (`S.past`, `S.future`), the playhead with its in and out points, the wipe, the viewer's colour, the fluid shot, the render state (`S.renders`, `S.heroKey`, `S.stage`) and the cache of uploads.

**The sections**, in file order, each opened by a `// ----------` line:

| Section | What it holds |
| --- | --- |
| Tuning | The tuning block. |
| What Klein sees | `editImage`, `maskAt`, and `captionFor` (the prompt writer). |
| Plate | `openPlate`, `warmAll` (models load at page open), the opening steps. |
| Decoded frames | The frame cache and the green stripe of cached frames. |
| Playback, as in RV | Play, pause, seek, in and out points. |
| The picture | `render`, `renderFluid`, the overlays (strokes, live previews, wipe). Once the shot of the current edits exists, it shows on every frame, paused or playing; frame 0 shows the edited first frame with the strokes only while edits are made, and the plate shows only in the wipe or while O is held. `#view` names what it shows in `data-picture`. |
| Painting | The pointer handlers, `rubOut`, `takeInputs`, `prepareSoon` (the prefetch), pan and zoom, with two fingers on a touch screen. |
| A fluid shot | `enterFluid`, `paintKey`, keyframe drag, copy and paste, `generateFluid`, `useFluid`, `openBlank`. |
| Edits | `launch` (with `reuse` and `keep`: a result is never made twice), `select`, `editingUI`, `nextEdit`, `pickTool`, `generate` (the two Klein passes), `prepare` and `prefetch`, `snapErase`, `rebuild` (what depends on a change runs again). |
| Undo and redo | `snapshot`, `mark`, `restore`. |
| History | `historyUI`: the list, bypass and removal. |
| In idle time | `pipeline`, `plan`, the render steps, the download. |
| Interface | Status, messages (`explained`: what failed, why in plain words from `plainError`, and what to do), the log, the size menu, the dialogs. |
| Scenes | Saving and opening a `.paintaplate.json`; `saveGraph` (the scene as one ComfyUI workflow). |
| The viewer's colour | Exposure, contrast, gamma, saturation, hue, channels and invert, for display only, as one WebGL2 shader on each frame (`display.mjs`). Once a value moves, an image-sequence plate and its export are read in their own values (`DeepFrames`, `/paintaplate/frames`), so lower exposure brings back what lies above white in an EXR. |
| The right-click menu | Every action with its key, also behind the menu button for touch screens; then `boot()`, the keyboard handler and `enter` (Generate). |

At load, `boot()` checks that every node class and model file the workflows need exists, and names what is missing.

## 12. Known limits

These come from GPU tests on an RTX PRO 6000 on 27 and 28 October 2026.

- An addition painted across a foreground object breaks up mid-shot: a scooter painted over a fountain's rim did. Paint additions in open space.
- An erased head comes back as a head. Paint the new head over the old one instead.
- An explosion painted on a moving car drives off with it. Erase the car first.
- A name finds that object only: « floodlight » found the lamp, and « floodlight pole » the pole.
- The paint matte takes what the shot changed within 1/16 of the width of the object's region. An effect that jumps further than that in one frame is not caught.
- After frames where the object is not seen, the matte searches up to 4 × 1/16 of the width around its last place: an object that comes back further away stays out.
- In a fluid shot, the painted colours win over the words: paint a dusk sky in dusk colours.
- A 4:2:0 video plate keeps about 42 dB PSNR after the export, even with a lossless encode, because of the round trip through RGB. Copying the untouched YUV samples from the source is planned.
