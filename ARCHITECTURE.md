# AInVFX Paint a plate: architecture

This document explains what Paint a plate does, how it is built and where each part lives, for anyone who maintains the code. It describes version 1.11.26. `TESTING.md` covers the tests.

## 1. What Paint a plate does

A **plate** is the source footage of a shot: a video file (MP4, MOV, MKV, MXF, WebM, or an animated WebP or GIF) or an image sequence (a folder of EXR, PNG, TIFF or DPX frames, or one sequence in a folder named by its frame pattern, such as `shot.####.exr`). You paint on the plate's first frame, and the change carries through the whole shot. There are three tools:

- **Paint** adds something new where you paint, from your text prompt: a fire, a boat, a lamp.
- **Clean** removes an object and regenerates the background behind it. In the code, the tool is `erase`. With **Whole object** on (the default), SAM 3.1 finds the whole object under the strokes, by its name when you type one.
- **Light** relights the scene from where you paint, in the colour of the brush.

Generate (the button at the end of the prompt bar, or Enter) starts an edit and its render. FLUX 3 Image Klein makes the edit on the first frame. The shot then renders by itself: LTX 2.5 carries the edits through every frame, SAM 3.1 tracks the changed areas, Follow Matte keeps every generated element inside the matte, and the result is composited onto the plate. With the Render panel's Preview on Half size or Quarter size, a quick preview pass comes first; then come the full-size passes, then the **review**: the full-size composite at the plate's own quality, which the viewer plays from then on. Generate never makes a result twice: an edit whose strokes, text prompt, seed and Whole object switch have not changed keeps its result.

**Export** writes the result for compositing software, only when you press it: the plate's own format (file type or codec, bit depth, frame numbers, colour tags, timecode, audio, EXR layers), with every pixel outside the edits the exact source pixel, and the matte. SDR to HDR on a plate whose format holds nothing above 1.0 is the exception: its result is half-float EXR frames in ACES2065-1 (section 14). Nothing is written for compositing software while you iterate.

**Colour** is managed with OpenColorIO, as OpenRV manages it. The config is the one `$OCIO` names, as in RV, else OCIO's built-in studio config (ACES 2.1, with the camera log spaces). Each plate has one colour space in that config, its **file colour space**: read from the file when the plate opens, and changed from the right-click OCIO menu. The viewer shows the plate through a display and a view; the models see the plate converted to the model space; the export converts the edited pixels back to the plate's colour space.

A **fluid shot** starts from a blank plate instead. You paint your fluid (smoke, fire, water and more) as flat colour keyframes, with optional flat zones for sky and ground. AInVFX's ainvfx-fluid IC-LoRA, trained on synthetic data (dataset `AInVFX/ainvfx-fluid`), turns them into smoke, steam, fire, explosions, water and other liquids, dust, fog or clouds in one LTX 2.5 pass. The result then becomes the plate for every edit.

**Keys.** P picks Paint, C picks Clean and L picks Light. E is the eraser, which erases strokes: it lasts while E is held during a drag, and a tap shorter than 0.3 s switches it on or off (`logic.eraserAfterKey`; in the code, `rub`). X toggles the X-ray. S opens Colours… over the frame (the swatches, the picker and the pipette, in a dialog that takes no focus) and T opens Text prompt… (the edit's text prompt; Enter applies it; RV's t toggles a heads-up timeline, which the page does not have), so full screen does the work. With the wipe on, comma steps its left side and period its right side through the plate, the first frame and the Render panel's finished steps. Ctrl+O opens a plate and Ctrl+S saves the scene: the page takes both from the browser. B and J are free. OpenRV's `e` is its exposure mode, which the page keeps on Shift+E.

## 2. Words used here and in the code

| Word | Meaning |
| --- | --- |
| Plate | The source footage of a shot. |
| First frame | Frame 0 of the plate, where every edit is painted. In the code, `S.original` is the plate's first frame in the model space, and `S.hero` is the first frame with every active edit stacked on it. |
| OCIO config | The OpenColorIO config in use: `$OCIO`, else a built-in config (`ocio://studio-config-latest` by default). `S.ocio.config` names it. |
| File colour space | The colour space a plate's values are in, by its name in the OCIO config (`S.plate.cs`). RV calls it File Color Space, and the OCIO menu shows it under « Plate (affects generation) » as « Colour space », and the log as « Plate colour space ». The viewer, the models and the export all use it. |
| Model space | The sRGB-encoded Rec.709 the models were trained on: the config's `sRGB Encoded Rec.709 (sRGB)` (alias `srgb_tx`, role `texture_paint`). In workflows, `@model`; `@linear` is the same space in linear light. |
| Display and view | How the viewer shows scene-linear values on the screen, such as `sRGB - Display` and `Un-tone-mapped`. The viewer only: they never change a result. |
| Edit | One change painted on the first frame: its tool (paint, erase or light), its strokes, its text prompt and its seed. The History panel lists the edits, numbered from 1 at the bottom. |
| Draft | The edit being drawn, before Generate (`S.draft`). |
| Current edit | The edit that new strokes, a new text prompt and the Whole object switch change: the edit just started, or the one picked in History (`S.selected`). The Editing tag in the prompt bar names it. |
| Text prompt | The edit's text: the field over the frame, or its dialog in full screen (T). `edit.prompt` in the code, the slot `words` in the workflows. |
| New edit | The action that closes the current edit, so the next strokes start a separate one: the N key, the button at the end of the prompt bar, or the right-click Edit menu. Picking another tool does the same. |
| Generate | The button at the end of the prompt bar, or Enter: it starts the draft or the changed current edit, then the render. Pressed with nothing changed, it runs nothing. Ctrl+Enter tries another seed. |
| Patch | The result of an edit: the new pixels of the first frame, as an RGBA image. |
| Pass | One run of a model. A Klein edit runs two: the edit preview, at 768 px on the long side, then a full-size pass. |
| Working size | The size edits are made at: the plate's size, at most 1920 px on the long side, in multiples of 32. |
| Preview pass | The shot preview: a first pass of the whole shot at a smaller size, shown before the full size. The Render panel's Preview menu offers Off, Latent preview (the default), Half size and Quarter size (`logic.readPreview`). Half size and Quarter size run a preview pass at half or a quarter of the working size on LTX's 32 px grid with the plate's aspect (`logic.previewSizes`, `logic.previewCap`). Latent preview runs none: each pass's live preview shows in the player. Off renders the full size alone, with no live preview. The choice is kept as `off`, `latent`, 2 or 4, for the session (`paintaplate.preview-menu` in `sessionStorage`): a reload keeps it, and a new session opens on Latent preview. A scene keeps no Preview choice, and the one an older scene holds is not read. On a blank plate with no fluid shot yet, and while a fluid shot's keyframes are open, the menu offers Off and Latent preview only (`previewUI`): no preview pass runs there, a size chosen for the session shows as Latent preview, and it comes back once the fluid shot is made. |
| Review | The full-size composite at the plate's quality, made right after the full-size passes. A video plate's review is a movie of its own values; an image sequence's review is also half-float EXR frames the viewer reads at full precision. Workflow `review`. |
| Export | The result written for compositing software, only when Export is pressed. Workflow `export`. |
| Matte | A black and white mask per frame: where an edit changed the shot. |
| Clean plate pass | The plate without the objects that Clean removes, in every frame (the clean plate), made by LTX 2.5 with Lightricks' in-outpainting IC-LoRA. Workflow `clean`; at full size, in Lightricks' two stages: `clean` at half the working size, then `cleanup`. |
| Shot | The plate regenerated by LTX 2.5 with WepeNerd's Ripple IC-LoRA, from the edited first frame. It carries paint and light. Workflow `shot`. |
| Composite | The shot's new pixels inside the mattes, over the plate's own pixels everywhere else. |
| IC-LoRA | A LoRA for LTX that reads a reference video next to the prompt (an in-context LoRA). |
| Prompt writer | FLUX 3 Image Klein's own prompt upsampler (Qwen 3.5 9B). It writes each edit's caption in Black Forest Labs' format. |
| Workflow | A ComfyUI graph in API format, in `web/workflows`. The page runs every step of its work as one. |
| Slot | A named input of a workflow that the page fills before it posts it: a path, a seed, a caption, a colour space. |
| Job kind | The group a posted workflow belongs to: `edit`, `snap`, `prefetch`, `warm`, `fluid`, and the render's kinds `clean`, `shot`, `matte`, `comp`, `hdr`, `review` and `export` (`BACKGROUND` in `app.mjs`). A cancel stops jobs by kind. |
| Hint | A sentence of the status line that says what to do next: `status(text, "hint")`. It never goes to the log (design rule 12). |
| Stop | Esc, or Stop beside Generate: what generates stops, and no job is posted until Enter (`S.halted`, design rule 13). |
| Layer | An edit, in History's order. While an edit is changed, the frame shows it and the edits under it (design rule 14). |
| Memory profile | What the page does on the GPU it runs on: `small` under 24 GB of VRAM, `medium`, `large` from 60 GB (`S.memoryProfile`, section 15). `warmAll` reads the GPU from `/system_stats`, sets the profile and loads what it names. |
| Example plates | The synthetic plates of the Hugging Face dataset `AInVFX/ainvfx-paintaplate`, which `get_plates.py` downloads into `input/plates`. |

## 4. Design rules

These rules keep the code small and easy to change. Follow them in every change.

1. **All GPU work is a ComfyUI workflow.** The page loads a workflow file, fills its slots and posts it. The 15 Paint a plate nodes only do what core ComfyUI cannot. So the app runs on any ComfyUI, and a Comfy API deployment stays possible.
2. **Workflows are generated.** `tools/build_workflows.py` writes `web/workflows`. Nobody edits the JSON by hand: a test fails when the files and the generator disagree.
3. **Each workflow describes itself.** In each node's `_meta`, `slots` maps the node's inputs to slot names, `output` names an output the page reads, and `progress` marks the node whose progress bar stands for the whole workflow.
4. **Optional links.** Some links exist only when the page has something to send: a matte to composite with, a name to search by, a relit frame, an image sequence's review frames. When their slots stay empty, the page drops the link and every node that fed it. The rule is written twice, as `OPTIONAL` in `logic.mjs` and in `build_workflows.py`, and a test keeps the two equal.
5. **Pure code is tested without heavy dependencies.** `plateio.py`, `mathops.py` and `ocio.py` need neither torch nor ComfyUI. Every module of `web/` except `app.mjs` and `canvas.mjs` runs in Node, with its tests in `tests/js`. `nodes.py` only converts tensors and calls them; `routes.py` is plain functions plus `setup()`.
6. **One edit at a time.** A stroke goes to the draft, else to the current edit if it has the same tool, else to a new edit (`strokeTarget` in `logic.mjs`). Another tool, or New edit, closes the current edit (`toolEndsEdit`). Undo keeps the current edit while it exists.
7. **Nothing made is lost, and nothing is made twice.** Changing the edit being generated (strokes, text prompt, the switch) stops its Klein pass. No render stops for that, nor for a bypass, an undo, a removal or a new edit: renders go on, and what they make stays. Results are kept per set of edits and per preview size (`S.renders`, keyed by `S.heroKey`), and what the erases make per set of erases (`S.erases`). Every finished job is also recorded in the job index on disk (`routes.py`, `output/paintaplate/jobs`), by the server's build (`routes.build_parts`: the pack's Python files, ComfyUI's version and commit, ComfyUI-LTXVideo's commit, or the hash of its Python files when it is not a git clone, and each model file's name, size and time; the line that ComfyUI's log gets at its start names that pack by its commit, or by its version and « files <hash> (not a git clone) »), the hash of its workflow file, the plate (path, size and time) and its values. A job with the same hash takes those files back instead of running, in this session or a later one on the same machine. A job is recorded only when every file it made is in the output folder (`recordable` in `comfy.mjs`, the rule `routes.write_job` enforces). A render of fewer edits, after a bypass or a removal, takes the frames of an earlier render of more edits when every edit left out is far from those kept and no light is involved (`logic.donorFor`, `donorOf`): only its tracking and composites run, and the Render panel shows the steps taken as "from v<n>". Render in full makes its own shot, with the same edits and seeds. After a change of code or of a model file, every job of a scene runs again once: a result made by other code or other weights never comes back. A new version number alone changes nothing. A page left open while ComfyUI restarts on another build asks for a reload, and keeps no index until then (`comfy.indexParts`, `comfy.onBack`).
8. **One colour space per plate.** The plate's file colour space is a name in the OCIO config. The viewer converts from it, the workflows convert from it to the model space, and the export converts the edited pixels back to it. Changing it makes the first frame and the edits again in it; the job index keeps the earlier results, so switching back takes them at once.
9. **Previews may trade quality for speed. The review matches the plate, and the export never trades.** The review of a video plate is a movie of its own values at the working size; the review of an image sequence is also its half-float EXR frames, which the viewer compares with the plate's own frames at full precision.
10. **Paths stay inside ComfyUI, or name a place on its own machine.** A path from the page resolves under ComfyUI's input or output folder (`folders.plate_path`), where symbolic links are refused. An absolute path names a place on the machine itself (`folders.machine_path`): a movie, a frame of a sequence (the whole sequence) or a folder, read only with a plate's extension, with symbolic links followed. It opens only when ComfyUI answers this machine alone, when every address it listens on is a loopback one (`folders.on_this_machine`): Load Plate reads its path inside a prompt, where no client's address exists, so only the listener limits who can name a place on the machine. The routes that read a path also refuse an absolute one in a request that a proxy passed on (`routes.this_machine`). On a server that listens on the network, a file goes through the page's upload. Nothing is written outside the output folder.
11. **One home per value.** Sizes, delays and budgets: the tuning block at the top of `app.mjs`. Model files: the constants at the top of `build_workflows.py`. Tested ComfyUI and ComfyUI-LTXVideo commits: `tools/pins.sh`. Model files and revisions: `get_models.py`.
12. **The log says each fact once, and the status line says what to do next.** The log records what happened, one line per fact: a size, a frame count, a memory figure or a file name appears in one line only. A job writes one line when it ends, with how long it took; it writes more only when it waits over a second in the queue, fails or is stopped. A sentence that tells the person what to do is a hint, `status(text, "hint")`: it shows in the status line and stays out of the log. `told(fact, next)` writes the fact to the log once and shows it in the status line with what to do next; `stopped(fact, next)` does the same for a page that cannot start, as an error. A GPU's memory, VRAM and RAM, is written in GB as bytes / 2**30, rounded: a 16 GB GPU reads « 16 GB » everywhere; a file's size and the frame cache's budget count 10^9 bytes (section 15). A plate that opens writes two lines: what it is (its size, its frames, its bit depth, its colour space and the seconds the open took), then the working sizes. Every message a person reads has one form: the thing and its state first, then the figure; a long message is a headline with detail lines under it, two spaces in; every message ends with a full stop. A log message takes its colour from its words (`logic.logLevel`): red when one of its lines starts « Error: », for work that stopped, and amber when one starts « Warning: », for something to check. A failure writes one fact in the log, and the status line adds what to do (`explained`, `logic.plainError`).
13. **A stop stops everything.** After Esc or Stop, nothing else starts until Enter (`S.halted`): an edit that waited keeps its turn, a stroke asks for nothing, and what finished is kept. A job of a kind the stop ends (`STOPPED` in `app.mjs`) is not posted while the stop is in force: `run()` in `comfy.mjs` asks the page's rule (`onStop`), so work that was between two jobs, such as a render step that uploads its images, ends as it does when its job is cancelled.
14. **Edits are layers.** While an edit is changed, the frame shows that edit and the edits under it (`layered`, `logic.hiddenAbove`). The edits above it are hidden and History dims their rows: they are likely to be generated again.
15. **One set of workflows for every GPU.** The memory profile only fills slots and decides what loads at start (`MEMORY` in `logic.mjs`, section 15).

## 5. The life of an edit

1. **Open a plate** (`openPlate`). The route `/paintaplate/stat` reads the plate's size, time and spec, and guesses its file colour space in the OCIO config (`ocio.guess`: the EXR's chromaticities or the video's colour tags, then the config's file rules). The `ingest` workflow decodes the plate once and holds it once: no node makes a second batch of it. It converts the first frame alone, with the whole plate's peak (`peak_of`), and saves it in the model space (at most 1920 px on the long side). Save Movie makes the playback proxy from the plate itself, one frame at a time. The plate spec goes out as text. A video plate's proxy keeps its own values at the working size, so the viewer converts it as it converts the plate; an image sequence's proxy holds log values (ACEScct in the built-in config) at 960 px, for playback while its own frames load. The page then sets its sizes: the working size, 768 px for the edit preview, 960 px for tracking (640 px for erase mattes) and the shot preview's size. An image sequence plays at 24 fps, or at the rate its EXR frames say (`framesPerSecond`, read by `plateio.exr_rate`).
2. **Paint.** Each edit draws on two canvases: `paint` (what Klein sees, for a paint) and `mask` (where the edit may act). `strokeTarget` decides which edit a stroke joins. I, or the pipette by the swatches, picks a colour for the brush in every browser (`pickColor`): the next click on the frame takes its colour (`pickAt`, `pickedColor`). On the first frame the pick reads the frame's own values, the ones Klein reads, with the paint in progress over them; on another frame it reads the pixels on show. A paint stroke shows at its own colour, through OCIO and the colour tools as the picture does (`strokes`), so a stroke of a picked colour cannot be told from the picture where it was picked, in any view. The browser's own eyedropper reads the screen, not the frame, so the page does not use it. The pipette's cursor is an eyedropper whose tip is its hotspot, so the tip is the pixel a click reads; while the pipette is on no swatch is lit, and a pick or a swatch ends it. A click on a History row shows that edit's strokes on the first frame and selects nothing (`show`); its pencil selects it (`select`). A stroke goes to the selected edit when the tool matches (`logic.strokeTarget`), else it starts a new edit on top. An undo ends the selection.
3. **Prepare while the strokes rest** (`prepareSoon`, then `prefetch` and `prepare`). `takeInputs` reads the text prompt and the Whole object switch into the edit. For an erase with Whole object, the `snap` workflow asks SAM 3.1 for the object by name and from up to five stroke points, and `pickObjects` keeps the right masks. Then the `prompt` workflow asks the prompt writer for a caption, and `reconcile` puts the page's boxes back into it. An erase sends one locked box per painted part (`paintBoxes`), and a caption that removes something the paint does not cover gives way to the page's own (`erasesPaint`). When that happens to an erase with no text prompt, the page asks the writer once more, with the same request, on the frame with every pixel outside the edit's mask at 30% of its light (`logic.dimOutside`, `dimFrame`), so that the object under the stroke stands out. The caption's headline then says that the writer saw the frame with all but the object dimmed. When the second answer still removes another object, the page asks for the object's name before Klein runs, and nothing renders (`logic.asksName`): the edit holds what the writer saw (`logic.removedNames`, `logic.writerSaw`), and History's row reads « Needs its name (the prompt writer saw the barn) » (`logic.askedText`). With a text prompt, the page's own caption carries it. An article typed before the name is dropped, so a request never reads « Remove the the barn ». An erase with no text prompt, painted in one part, asks the prompt writer with one box: the stroke and what most of SAM's masks hold, with no margin (`logic.coreBox`, `logic.writerBoxes`). A wider box can take in a neighbour, such as the horse's nose beside the barn, and the writer then removes the horse. Other edits keep one box per painted part. A paint whose text prompt names no colour names the colours that its strokes show, largest share first, in the prompt writer's request and in the page's own caption (`logic.colorShares`, `logic.paintColors`); a text prompt that names a colour wins. For a Clean that takes the whole object, when the prompt writer's caption cites the object's cast shadow, SAM 3.1 finds the shadows by the word « shadow », and those that meet the caption's box and touch the object, or lie under it, join the object's SAM mask (`logic.shadowBox`, `logic.shadowOf`, `joinShadow`); a mask over three times the object's area is the scene's shade and stays out. A relight asks no prompt writer: its request is the page's own (`logic.lightIntent`), and the status line names the prompt writer only while Generate waits for it. Every line written while the strokes rest carries the number that the edit takes in History (`num`). A new stroke cancels this work.
4. **Run the edit** (`launch`, then `generate`) when you press Generate (Enter). An edit whose strokes, text prompt, seed and switch match a result it already made takes that result back (`reuse`, up to `RESULTS_KEPT` results per edit, each kept by its plate, strokes, text prompt, seed and switch and by the edits under it: `keep`). Ctrl+Enter tries another seed. The `edit` workflow runs twice: the edit preview at 768 px on the long side (16 steps, denoise 1, with live previews inside the strokes), then a full-size pass from that result (8 steps, denoise 0.35). The result is the edit's patch. For an erase, the full pass ends in Level Fill, which levels Klein's fill with the background around it: left in, a pale imprint of the removed object would become smoke in the clean plate pass. The `edit` workflow saves its outputs to the output folder, so the job index finds them later. After an erase's full-size pass, the page compares the first frame with the frame under the edit inside the object's mask (`logic.erasedShare`). When the check finds the object still there, the page asks first, in its one question dialog (`heldBack`, `logic.leftLines`, `ask`): « Yes, render anyway », clicked or by Enter, keeps the first frame and renders its shot; « No, cancel » or Esc drops the result and leaves what to do next in the status line (`leftHint`). After « No, cancel », nothing of that edit runs again until its text prompt, its strokes, its seed or its switch change (`edit.refused`): neither Enter after a stop nor a rebuild runs it, and Generate on the unchanged edit says again what to do. History's row is marked as the question opens. The check holds an erase back when: under 30% of the object moved by more than 24 levels, or its edges held above 0.85 (`logic.eraseCheck`). A rule of under 2% at 12 levels would pass a barn that Klein only recolours. The page also measures the band that the edit reaches beyond the object's mask (`logic.bandBeyond`, 22 px at the edit preview's 768 px). When over 20% of its cells move by more than 24 levels (`logic.BEYOND`), Klein has removed a neighbour with the object: the erase is held back with the same question, and History's row reads « The area around the object changed ». An erase that passes writes that band's two figures as a detail line.
5. **Stack the first frame** (`recompose`). Active patches stack on `S.original` to make `S.hero`. When an edit changes, the edits above it run again only if they depend on it (`dependsOnChange`: one of the two is a light, or their footprints overlap on a 96-cell grid). While an edit changes, the first frame shows only the edits below it (`firstFrame`), and the status line's note names the ones it hides (`logic.hidesNote`, `noteUI`).
6. **Render** (`idle`, then `pipeline`), from the render queue. Every set of edits shown is a render (`want`), made from a copy of its edits (`freeze`). One step runs at a time, for the set of edits on show alone (`pickRender`): its preview, then its full size, then its export. Once its full-size composite is made, nothing computes until an edit changes, another set shows (an undo, an eye, a History row) or Export asks. A set no longer on show waits (`YIELD`) and goes on at its next step when it shows again. Nothing stops a step but Generate, which stops a full-size or export step in its first half (`preempt`, `logic.stopsForEdit`); that step runs again when its edits are turned on again. `plan` skips the steps an edit set does not need:
   - `matte` at 640 px tracks each erased object (SAM 3.1, then Follow Matte: one matte per frame even when SAM returns none, the last matte where SAM loses the object, and no other object SAM finds by itself);
   - `clean` makes the clean plate pass: each erased area as blocks of LTX's 32 px grid, grown by one block, and a prompt that describes the scene as it stays (`erasePrompt`), never the erased object;
   - `shot` regenerates the shot over the clean plate (or over the plate when nothing is erased), for paint and light;
   - `matte` tracks each painted area, and Follow Matte adds every pixel the shot changed near it, compared with the plate the shot was made over. The paint matte starts from the pixels the edits changed on the first frame (`changedMask`), not from the whole paint zone. SAM 3.1 is prompted with the paint zone and returns that zone on its first frames (10 to 13 on the cow): on those frames the matte of an object that stands still is its place of frame 0, moved with the background. SAM 3.1 can shrink from the zone to the object over several frames: until its mask first comes within twice the object, a mask of twice the object or more is the zone too. On those frames the matte also keeps what the shot changed joined to the object's place, so a part that moves, such as a wing that opens, stays in. When something the plate holds passes in front of a painted object that stands still in the scene, the matte leaves out what stands in front, is empty while the object is hidden, and takes the object again where it comes out; An erase reads the frames it tracked as the plate: an erased object that stands still and passes behind something leaves the matte while it is hidden, and the matte takes the tracker's mask again where the object comes out. A piece of the tracker's mask that lies mostly on what the plate holds in front is left out, for a paint as for an erase. When less than a quarter of the object's place holds the object, a found area that reaches beyond the place's margin is left out whole, and once all that was found has left the place no last matte holds. A painted object that leaves its place for good is lost: from the first frame where all that was found has left the place, with the object never seen there again, the matte holds nothing, and the summary warns. The tracker's mask counts as the paint zone only when it lies mostly inside the zone. A paint over a Clean edit: the `matte` workflow gives Follow Matte the Clean matte and how far the composite moves its edge, its grow plus its feather (`erased`, `erased_edge`). Inside the Clean matte so grown, a change joins the paint's matte only where it touches the SAM mask, within a zone of it; painted smoke that drifts over the cleaned place away from its source is cut there. The summary is a headline, the warnings (an object that left its place; a matte above 3 times the object, with its frames), then one line per rule that acted, the flicker last. Around the object's place, the covered part of a changed area joins the matte by its thick part only (an opening by 1/240 of the width): a thin covered line there is the edge of what stands in front. A paint's matte keeps, of what the tracker found, the pieces the shot changed that lie within a zone of the matte of the frame before (of the first-frame mask on frame 0), each piece whole and grown by 1/240 of the width inside what was found. SAM 3.1 can return a whole horse for a paint on its body: the part of the horse that the shot left as the plate goes back to the plate, and specks of change far from the edit stay out. When no changed piece joins, the matte of the frame before holds where the object is found. The object's region, the search and the test of an object that stands still follow what was found, as before; an erase's matte is unchanged.
   - `comp` makes the composite at the preview size, in the model space.

   Then the same passes run at full size, without waiting for anything: at full size the clean plate pass runs in Lightricks' two stages, `clean` at half the working size (the preview's own pass when the preview is that size), then `cleanup`, 2 steps at full size. The clean plate pass grows its erased grid as far as the composite pastes an erase (`logic.gridGrow`), at the size of each pass. It stays a test option: the half-size first stage decides what the shot shows, so the picture can differ from the one-stage shot's. The viewer plays the full-size shot as soon as it is made: the preview size can lose an effect that the full size keeps. With the Preview menu on Latent preview or Off, the four preview steps join the render's skip set (`plan`): the render starts with the full-size passes, the Render panel lists no preview row, and the viewer keeps the plate until the full-size composite. Last comes `review`, the full-size composite in the plate's own colour space, which the viewer plays from then on (`r.review`; for an image sequence, its EXR frames too, `r.reviewFrames`). For a set of Light edits only, the composite is Relight Transfer, so its steps read « Light transfer, preview » and « Light transfer, full size » (`logic.stepLabel`); their times stay under `comp` and `review`.
7. **Export**, when you press Export (`S.wantDownload`). The `export` workflow makes the same composite, then Save Plate writes it in the plate's format with the exact source pixels wherever nothing changed (a video plate's own YUV samples), or, when SDR to HDR ran on a plate whose format holds nothing above 1.0, Save Frames writes half-float EXR frames in ACES2065-1 (`logic.exrResult`); and the matte frames, beside the review. The route `/paintaplate/download` zips the parts ticked in the Export dialog. With « ComfyUI graph » ticked, the page builds the scene's graph (`graphFile`) and posts it to `/paintaplate/graph`, which writes it into the run's folder as `scene.comfyui.json` for the zip: a workflow in the editor's format, of 16 MB at most, written whole so that a symbolic link of its name is never written through. When that route does not write it, as on a ComfyUI not restarted after an update of the pack, the zip comes with the other files and the page warns. A render that is not on show never exports. For an edit that keeps the plate's untouched pixels, Export also writes the layer: the shot as the composite blends it, at the plate's size, in the plate's format (half-float EXR in ACES2065-1 beside an EXR result), so result = plate × (1 − matte) + layer × matte. The layer is black outside a window around the matte, where Fit to Plate does not work: the composite never shows it there. With Finish > Upscale on, its step follows (section 6).

Every LTX pass shows a live preview unless the Preview menu is on Off: at every step, the Live Preview node decodes the frames LTX predicts into a looping WebP, which the player shows over the frame (section 6, « Live previews and stopping »).

## 6. Colour, as OpenRV does it

1. **The config.** `ocio.py` loads `$OCIO` when it is set, else a built-in config; the page can switch among them (`/paintaplate/ocio` lists them). It never opens a path the page sends.
2. **The viewer** (`display.mjs`). Each source is drawn through one WebGL2 program, in the order OpenRV chains its nodes under OCIO: `ocioIn` (the source's colour space to scene-linear, as OCIOFile), the colour tools in scene-linear as RVColor (`ColorIPNode.cpp`): gamma first, then one matrix built in RV's order (invert, exposure, contrast about 0.5, hue, saturation), then `ocioOut` (the look, then the display and view, as OCIOLook and OCIODisplay), then the channel shown as grey, picked from the display values, as OCIODisplay floods a channel after its OCIO function. OCIO writes `ocioIn` and `ocioOut` as GLSL ES 3.0 on the server (`/paintaplate/ocio/shader`), with their lookup tables as float textures. A program is made once per colour space and view, so changing either applies at once, also while the shot plays. When the whole chain changes nothing (an 8-bit frame through an identity view, the colour tools at their defaults), the frame is drawn as it is.
3. **What each source is in.** The plate's own frames, a video plate's proxy and its review: the file colour space. The first frame, the patches, the live previews, the preview composites, the shots and an image sequence's review movie: the model space. An image sequence and its review are read as RGB half floats (`DeepFrames`, `/paintaplate/frames`), around the playhead, as OpenRV's cache keeps an EXR's half floats.
4. **The menu.** Right-click, then OCIO. Two headings: « Plate (affects generation) » and « View (display only) ». Under the first, « Colour space » (RV's File Color Space), a tree by colour-space family: its line ends with « from file » for the file's own value, or « override » once the person chose another (`logic.plateSpaceLine`). Under the second: View (the views of the display in use), Display, and Look when the config has looks. Then Config. A new colour space or a new config regenerates the edits, so the page asks first when an edit has a result: « Changing the plate's colour space affects generation: 1 edit will be regenerated. Continue? », with Continue and Cancel (`logic.remakeQuestion`). The page has one question dialog, `ask`, and one question at a time: a question that comes while another is open waits for its answer. In the plate's tree, the config's family « Display » reads « Display-referred » and its family « ITU » reads « ITU (International Telecommunication Union) » (`logic.plateFamily`); RV and Nuke show the config's own names, « Display » and « ITU ». View, Display and Look never ask. Each line shows its value. RV binds no key for OCIO; neither does Paint a plate. The display, the view, the look and the config are kept for the next session.
5. **The workflows.** Colour Space (OCIO) converts the plate to the model space as core ComfyUI's Convert Image Color Space made sRGB: values above 1.0 tone-mapped with the batch's peak, then a gamut compression (`ocio._into_model`). Out of the model space, values are decoded as they are. Relight Transfer works in `@linear`.

**SDR to HDR** (on whenever its files and nodes are found: `HDR_ON` in `app.mjs`, `?hdr=0` turns it off). The `hdr` workflow is Lightricks' official LTX 2.5 SDR-to-HDR graph: the shot mapped from sRGB to ACEScct by core Convert Image Color Space as the IC-LoRA's guide, fixed scene embeddings for the prompt, CFG 1, 8 distilled steps, and a decode by the video VAE, which core's VAE Loader loads and core's VAE Compute Dtype sets to compute in float32: core's VAE Decode (Tiled), which takes the whole frame in one piece from 16 GB of VRAM (« The decode's tiles », below). Colour Space (OCIO) then turns the decoded ACEScct codes into ACEScg scene-linear values with the config's own conversion, each frame written into one array (`ocio._fill`), and Keep Black takes the SDR shot as loaded, converts each of its frames as it uses it and lets no value fall below 0. The frames are saved as half-float EXR in ACES2065-1 (the file rules' space for EXR). The page runs it after the full-size shot (`step(r, "hdr")`) when `logic.wantsHdr` says so: no light edit, and the rule that follows. With a Light edit, on a plate whose format holds nothing above 1.0, it runs on the relit composite instead, once that is made (`logic.hdrAfterComposite`), as on a plate with no edit: Relight Transfer relights the plate itself, and the shot's HDR frames reach the result only inside the mattes, so the composite writes its EXR frames, SDR to HDR makes them HDR whole, and Export zips those frames (`exportAlone`). It runs on its own for new content on a plate that holds values above 1.0 (`logic.wantsHdrFor`, `holdsHdr`); on any other plate only when the Finish menu asks for it, and then the render key gains `|hdr`, so each setting keeps its renders. A plate holds values above 1.0 when its samples are float or when its colour space decodes code value 1.0 above 1.0 (`logic.holdsHdr`; `headroom` comes from the stat route: a log encoding, PQ or HLG), video or not, and then it exports in its own format with no extra files. Otherwise (an SDR video, an integer sequence in sRGB or a linear encoding) the Finish menu's SDR to HDR converts it on purpose, asked first under its row (`askFinish`, `#finish-hdr-ask`), and the result becomes an EXR sequence (`logic.exrResult`). Its review also writes half-float EXR frames in the plate's colour space with values above 1.0 kept, which the viewer reads at full precision as an image sequence's, and its export drops Save Plate (the optional link `export_plate`) for half-float EXR frames in ACES2065-1 (`export_exr`). `review` and `export` load its frames, convert them to the plate's colour space and fit them with HDR Match (`mathops.hdr_match`): one gain per channel and per frame, the median ratio to the plate's own values over the frame's untouched mid-tones (plate luminance 1/64 to 0.71), since SDR to HDR's level drifts over a shot (0.2 stops over 121 frames of `horse.mp4`). The gains are smoothed over 9 frames, each as the value of a straight line through its neighbours' gains (`mathops.smooth_gains`), so the level follows the plate with no flicker; a frame with too few untouched mid-tones takes its neighbours' line, or the whole shot's gain. A gain changes no ratio, so the range SDR to HDR made above the plate's white stays for grading. Without HDR frames the `hdr_shot` link goes and HDR Match passes the SDR shot through. A 16-bit blank plate runs its fluid shot through `hdr`; the EXR frames become the plate under the edits, and they say the blank plate's frame rate. The page turns SDR to HDR on when every node class that `hdr.json` holds is present (`logic.workflowClasses`) and its model files are found. The `hdr` workflow takes a shot, or a plate with no edit, which is its own SDR shot. For a plate, the slots `color_space`, `width` and `height` bring it into the model space at the working size, and `plate_width` and `plate_height` bring the HDR frames back to the plate's size, where HDR Match sets them to the plate's level with an empty matte: nothing changed, so each frame's mid-tones give its gain per channel. For a shot no plate size is given: the optional link `plate_level` goes, and Colour Space (OCIO) from the model space to itself, core's Upscale Image at 0 x 0 and HDR Match without a plate each pass their input on with no copy. Save Frames and Save Movie keep Load Plate's frame count, so the 8n+1 padding that LTX needs stays out of the result. On a plate with no edit, the Finish menu's SDR to HDR gives the render key `|hdr` (`logic.renderKey`, `plateAlone`). Turning it on starts nothing: Generate makes that render, and the status line says so with its time. Its one step runs `hdr` on the plate (`plateHdr`), the viewer plays its frames in ACES2065-1, and Export zips them as they are (the download route's part `hdr`). `tests/hdr_plate.py` runs the same job on a running ComfyUI (its `finish` command).

**Upscale** (the Finish menu's second row, off by default; when SeedVR2's files or core's SeedVR2 nodes are missing, the row is off with one warning line, and the page starts). With the row on, a list gives the sizes for this plate: its own, then 2560 and 3840 px on the long side when they are larger, then Custom…, which takes the long side in px, from 640 to 3840 (`logic.upscaleSizes`, `upscaleCustom`). The row turns on with its switch, with no question. Under the list, a note gives about how long the upscaled set takes on this GPU, the plate and the layer included for a Paint or a Clean (`logic.upscaleNote`, `upscaleFigures`). A custom size in use is an entry of its own above Custom…, which opens its dialog each time, on the size in use. Every size keeps the plate's aspect within 3840 x 2160, with both sides even (`upscaleTarget`): a 4:3 plate gets 2880 x 2160. A scene holds the size asked for under `deliver.upscale`, and a scene saved with the switch alone opens at 3840 px on the long side (`upscaleAskOf`). The row adds a step after Export: SeedVR2 7B restores the export at that size, from a third of it (`UPSCALE.factor`: a larger result comes down to a third first, a smaller one goes in as it is; core's SeedVR2 nodes pad the frames to a multiple of 16 and crop them back, so every size comes out exact). It works in windows the machine's memory holds (`logic.upscaleWindow`): one job on a 96 GB GPU; on a 16 GB GPU under a 52 GB cap, windows of 21 frames at 3840 x 2160, and longer ones at a smaller size. For Paint and Clean the upscaled set has four parts: the plate and the layer, each restored, the matte resampled with a bilinear filter, and the result composed from them window by window in the layer's job; outside the matte, the upscaled result is the upscaled plate. A plate's windows are kept under its folder and serve its next export through the job index; a result's windows sit under `upscale/<width>x<height>/` of its export, so each size keeps its own. For Light, a fluid shot, a plate alone with SDR to HDR, and every result that SDR to HDR made, SeedVR2 upscales the result alone, with its matte when it has one (`upscaleAlone`, `logic.upscaleComposes`): SDR to HDR regenerates every pixel, so a set composed from the SDR plate would lose its values above 1.0 outside the matte. SDR to HDR runs before Upscale: generated at 3840 x 2176 after the upscale, it takes ten times as long (1,811 s against 178 s for 121 frames of a 1920 x 1080 plate on an RTX PRO 6000), needs 78 GB of VRAM and keeps fewer values above 1.0. Save Plate writes each part in the format of its plate-size twin, under `upscaled/`.

**SDR to HDR's temporal tiles.** A flicker in SDR to HDR's frames had two causes. In the files: Lightricks' distilled graph decodes in 64-frame temporal tiles with 8 frames of overlap, and the HDR frames of a 121-frame fluid shot jumped 0.32 stops at frame 56, where the second tile starts (RTX PRO 6000). The `hdr` workflow decodes in 128-frame tiles with 32 of overlap, as Lightricks' Tiled Fusion graph: the largest step fell to 0.07 stops, the SDR shot's own, and a shot of up to 128 frames is one tile.

**The decode's tiles.** Every LTX decode that the memory profile sets (`shot`, `cleanup`, `fluid`, `hdr`) is core's VAE Decode (Tiled) with the slot `tile`. In tiles, each tile comes out brighter near its edges, and the blend of two tiles leaves a band where they overlap. Against the same latent decoded whole (121 frames at 1920 x 1088, RTX PRO 6000; `tests/hdr_plate.py bands`), SDR to HDR's frames held bands of 0.10 to 0.18 stops with 256 px tiles and of 0.12 to 0.19 stops with 512 px tiles, 64 px of overlap each, and an SDR pass's frames held 3.5 to 3.9 8-bit steps. No tiling measured leaves no band: tiles up to 1024 px, with overlaps up to a quarter of the tile, or half with the VAE's own tiled decode, left 0.06 to 0.14 stops. So the slot's default is `WHOLE`, 4096, the node's largest tile: a tile larger than the frame takes core's single-tile path, with no blend, and VAE Decode (Tiled) has no retry after an out-of-memory error, so core's default tiles never take over. Decoded whole, the 121 frames took 13 s at a peak of 10.3 GiB of VRAM in float32, against 45 to 99 s in tiles (`tests/decode_cost.py`). An IC-LoRA guide encoded in tiles leaves its own lines in the shot sampled from it, on the same grid, so every guide is encoded whole too (`guide_tiled` false): 7.5 s at a peak of 7.3 GiB, against 13.8 s in 256 px tiles. The full-size clean plate pass encodes its first stage whole as well (slot `encode_tile`): encoded in 256 px tiles, its frames show bands of 0.3 to 1.2 8-bit steps where two tiles overlap, and up to 0.05 stops through SDR to HDR (121 frames at 1920 x 1088, RTX PRO 6000; `tests/hdr_plate.py bands`). Under 16 GB of VRAM the page sends 256 px tiles and a tiled guide, with their bands (section 15).

**The viewer's 8-bit movies of an image sequence.** The second cause was in the viewer. It drew an image sequence's EXR frames where they had arrived and its 8-bit movie elsewhere, and that movie was in the model space, tone-mapped with the shot's peak (a white of 1.0 shows at about half its value at a peak of 15). Its 8-bit movies now hold log values (`logic.viewerSpace`: ACEScct when the config has it): the playback proxy (`proxy_space` of `ingest`), the review's viewer movie (output `view`, the optional link `review_view`, dropped for a video plate) and the SDR-to-HDR movie (output `movie`). While a source plays, it shows its EXR frames only once all of them are in (`logic.drawsDeep`, `holds`); paused, the precise frame shows. The review movie of the zip stays in the model space.

**Two passes in the wipe** (Ctrl+click on a finished Render step, Cmd+click on a Mac). The wipe's left side shows that pass against the displayed result on its right, both named, to find the step a fault comes from: a shot against its composite, a matte against the picture, a preview against the full size. A second video plays it beside the shot: a follower of the playhead (`followers` in `app.mjs`), synced by `tick` and `seek`. Paused, its frame comes at native size from the frames route, as the right side's does, and the plate shows on the left until it has one. A second Ctrl+click, Esc or F6 ends it, and the wipe goes back to how it was. The Colour Inspector reads the side of the wipe its point is on (`inspector.wipeSide`): the plate, the pass compared or the pass on show, named in its Source row. The pixel route takes the plate's size (`of`), so a pass with fewer pixels, such as a preview, is read at the same place in its own pixels: 1.7.0 read the plate's pixel numbers there and failed.

**The X-ray** (X, free in OpenRV's `rvui.mu`, where Shift+X flops the image), as PlateLock's: where the edits turned on change the plate, tinted over the picture. `xray.xrayPlan` picks the matte: the export's once Export has made one; else the matte the composite of the size on show blended the shot in with (the `matte_movie` output of `comp` and `review`: Fit to Plate's mask, aligned to the plate, grown and feathered as the composite's); until a composite exists, the tracking mattes (the erase matte and the paint matte). A light edit changes every pixel, so it tints the whole frame. The tint is drawn on its own canvas, `#xray`, above the picture with its zoom and pan, so the inspector's final colour and the colour picker read the picture without it. Each matte's frames come from the frames route at 512 px (`XRAY_SIDE`), in any browser, 16 a request with the frame on show first, and stay in memory at one byte a pixel (`xrayLoad`): playing or paused, the tint is the mattes' frame on show, and playback stays in memory. Until every matte has the frame, the last tint stays. Frames that the route cannot read show no tint, and the log says so once.

**Full screen** (View > Full screen, or the backquote key; `fullScreen`): the plate alone, fitted, with no panel, menu bar, timeline or status line. The page also asks the browser for its own full screen; where the browser refuses, the plate fills the window the same way. The right-click menu and every key work. When the frame changes, the plate's own frame number shows for a moment in the HUD's corner. Esc or the backquote key comes back to the zoom and pan it left.

**The viewer against OpenRV.** The colour tools are RV's own math, in `display.mjs` (`colorMatrix`, `displayUniforms`), read from OpenRV `0bd9675`: RV multiplies each tool on the left of one 4 x 4 matrix (invert, exposure, contrast as (1 + c) x - c / 2, hue as a sheared rotation about the grey axis that keeps Rec. 709 luma, saturation), and its shader applies gamma before that matrix. Contrast is 0 at rest, as RV's `color.contrast`. RV's invert matrix carries (1, 1, 1, 0) as its last row, so contrast after an invert scales its offset by r + g + b; the viewer keeps that, for RV's values. `ocio.py` asks OCIO for the GPU processor OpenRV asks for (`OPTIMIZATION_DEFAULT`), in GLSL ES 3.0 instead of RV's GLSL 1.3. `tests/test_rv_parity.py` holds the reference (RV's math, with PyOpenColorIO's CPU processor in place of RV's GPU one) and `tests/flows/viewer.py` reads the canvas for 12 pixels and every case.

**OpenRV `0bd9675`, read line by line against `display.mjs` and `ocio.py`:** `ColorIPNode.cpp` (gamma's exponent is 1 / gamma, applied first as `pow(max(x, 0), exponent)` in `ColorGamma.glsl`; then one matrix, each tool multiplied on the left: invert with its (1, 1, 1, 0) last row, exposure, contrast (1 + c) x - c / 2, hue iR * iZsh * Rz * Zsh * R, saturation with `Rec709FullRangeRGBToYUV8`'s first row, 0.2126001, 0.7151999, 0.0721999; offset, scale, CDL and the luminance LUT stay at rest in Paint a plate), `OCIOIPNode.cpp` (`getOptimizedGPUProcessor(OPTIMIZATION_DEFAULT)`, the channel flood after the display with the same weights) and `ocio_source_setup.py` (OCIOFile, RVColor, OCIOLook, OCIODisplay). No difference in values. Paint a plate's weights are 0.2126, 0.7152, 0.0722: 1e-7 apart, far below one code value. With no OpenRV to run, the parity stands on this reading and on `tests/test_rv_parity.py` with the canvas readback (23 cases, 1 code value at most).

**The colour inspector** (`inspector.mjs`, F5, View > Colour Inspector, as `toggleColorInspector` in `rvui.mu` and `inspector.mu`, with annotate mode's rules from `annotate_mode.mu`, OpenRV `0bd9675`). The inspector and the brush are active at once: a plain click paints; Shift+click samples a pixel and Shift+drag averages the pixels it passes (RV's `pointer-1--shift` binds, which annotate mode passes on). The box sits beside the sampled point with a marker on it, and dragging the box moves the point with it (RV's widget drag). The point lives in the plate's own pixels (from the top left) and every redraw reads it again (`refreshInspector` at the end of `render`, `renderFluid` and `applyView`), so the values follow the frame, the source, the pass on show, zoom and pan. The source values come at full precision and native size from `/paintaplate/pixel` (`routes.pixel`: an EXR's half floats as stored, a video's frame decoded with its own YUV matrix and range); the final colour is read from the canvas. It reads the file on show: the shot's EXR frames in their own space (`setShot`'s `framesSpace`), else its movie, whose codes it names as such, else the plate.

**The plate at its own size.** The canvas holds the plate at its native size, up to 4096 px on the long side (`NATIVE_SIDE`, the frames route's limit and the pipeline's movies'), and key 1 shows it 1:1 in device pixels (`display.pixelScale`), as RV's 1:1. Editing stays at the working size: strokes, edit previews and the brush draw through one scale (`inWork`), and `frameAt` returns working-size pixels. Paused, the frame on show comes from the frames route at native size and full precision, one frame per source (`sharpFrame`: the plate, and the shot's EXR frames or movie), so an EXR shows its half floats and a video its source frame, decoded on the server (`routes.video_frames`: planar YUV through the file's own matrix and range in float, from its samples at their bit depth). While a source plays, the movies and the 960 px cache stay. From 1:1, the canvas draws with `image-rendering: pixelated`, so a plate pixel shows as a square.

**Zoom and pan as OpenRV.** The bindings of `rvui.mu` (`0bd9675`): f fits, Ctrl+F fits the width (RV's Frame Width), 1 to 8 show N:1 and Shift+2 to Shift+8 show 1:N in device pixels (RV's Ctrl+2 to Ctrl+8; Chrome keeps Ctrl and Alt with a digit for its tabs), Ctrl+drag zooms about the press point with RV's `dragZoom` curve (to the right k + 15 m², to the left k - 0.75 m, m = |dx| / width x k x 2), Alt with both buttons zooms too, Alt+drag and the middle button pan, Shift locks the pan to one axis; the wheel steps frames, as in RV. The math is pure (`display.mjs`: `pixelScale`, `dragZoomScale`, `zoomAbout`, `lockAxis`, `pointIn`), and `frameAt` maps the pointer through the view's laid-out box, so a stroke lands under the pointer at every zoom.

**The wipe on a fluid shot.** With the keyframes open and a shot made, the wipe shows this frame's painted keyframe on the left, or black where the frame has none (no onion skins), against the shot on the right; the left label reads « Keyframe ».

**The colour tools while a source plays.** At rest a playing source shows its 8-bit movie until all its EXR frames are in. Once a colour tool moves, a source with EXR frames shows only those (`display.exactFrame`: the frame on show, else the nearest one in), as RV plays what it has decoded: four stops up, the 8-bit ACEScct movie of a fluid shot was 4 display levels off at the median and 24 at p99 in its dark background, with H.264's 8 px blocks.

**Models and licences** (`web/models.json`, `models.mjs`, Help > Models and licences). The registry holds every model file with the licence its Hugging Face repository states at the pinned revision, the original model's licence where a repackaged file differs, its source and its use; `tests/test_models.py` checks it against `get_models.py` and every workflow. The view lists the models behind the result on show, from the files the workflows that made it load (`logic.resultFlows`, `modelsBehind`), then every model.

**Passes on show.** The Render panel's finished rows with a movie (`logic.PASSES`, `passMovie`) and a First frame row: `choosePass` sets `S.pass`, the viewer shows that pass on every frame, and the pipeline's own `setShot` calls wait until `S.pass` is null again (a second click, Esc after the selection, or other edits). The clean plate pass keeps its own movie as `cleanRaw`. The tracking steps and the export show their matte: the `matte` and `export` workflows also save it as a grey movie (optional outputs, dropped when the page sends no prefix, as in the ComfyUI graph), drawn through the config's data colour space (`logic.dataSpace`, OCIO's isdata, such as Raw), so it shows its own values. A made fluid shot has its own rows, with its keyframes open or closed (`logic.fluidPasses`): Fluid: keyframes (the control video, an optional output of `fluid`), Fluid: shot, and for a 16-bit plate Fluid: SDR to HDR.

**Start and the fluid export.** With no plate open, boot opens a blank plate at the Blank tab's settings (`BLANK_AT_START`, `openBlank({ atStart })`), 16-bit when SDR to HDR is ready (`logic.defaultDepth`). A fluid shot with no edit on it exports itself (`fluidOnly`, `downloadFluid`): the download route's parts `hdr`, `plate` and `preview` of its folder (`logic.fluidRun`).

**Dropped links** (`drop_link`, `dropLink`) also remove the nodes that only fed what went, so a filled workflow holds no node that feeds nothing.

**Finish** (`#finish-btn`, `#finish`, `finishUI`): the menu of the passes on the whole plate after the full-size composite, between Save scene and Export. Each pass is one entry of `logic.FINISH`: its id, its name, the line that says what it does to the result, and the question it asks before it turns on, when it has one: SDR to HDR asks, and Upscale turns on with its switch. The row, its question, the line that says why it cannot change on this plate and the button's count (`logic.finishLabel`, « Finish · 1 ») come from the entry, so a new pass is one entry and its render step. The button's tooltip is written once, in the page (`FINISH_TIP`), and `finishUI` adds the passes turned on. Its first row is SDR to HDR: the deliberate conversion of a plate whose format holds nothing above 1.0 (`S.deliver.hdr`), confirmed first under its row, delivered as an EXR sequence (`logic.exrResult`). On a plate that holds values above 1.0 the row shows on and greyed, since SDR to HDR runs on its own there. Esc, a click outside or the button closes the menu, and a question left open closes as « Cancel » does. A scene keeps these choices under its key `deliver`, so older scenes open unchanged. The other passes (upscale, alpha, depth, normals, IDs) come next, each model in `web/models.json`.

**The workflows a render ran** (`r.flows`). Each finished or reused step adds its workflows to its render's record (`logic.STEP_FLOWS`: a full-size clean plate pass runs `clean` and `cleanup`). An export's `MODELS.md` names the models behind its result from that record, the edits' own workflows (the prompt writer and Klein, SAM's object search for an erase) and a fluid shot's (`logic.resultFlows`, `modelsBehindResult`), so a step that never ran, such as SDR to HDR on an SDR plate, lists no model; `STEP_FLOWS` names the upscale step's workflows, so an upscaled export names SeedVR2. Models and licences plans the job on show from its start (`jobFlows`): the edits on show and the one being painted, every step their render runs, Upscale and SDR to HDR when Finish asks for them, a fluid shot. Each model of that set is tinted over its whole card, and the tab follows the plan while it is open.

**New content at the plate's bit depth** (`logic.plateDepth`, read from the plate's pixel format). The frames a shot and the clean plate pass pass through on their way to the export are 8-bit PNG for an 8-bit plate, 16-bit PNG for a 10, 12 or 16-bit plate (10-bit and 12-bit video, ProRes among them, 16-bit PNG and TIFF, 10-bit DPX), and half-float EXR for a plate of floats, EXR or a float TIFF or DPX (Save Frames' `png`, `png16` and `exr`, the `frames_format` slot of `clean`, `cleanup` and `shot`). The export already writes each plate at its own depth (Save Plate), so the new content keeps more than 256 levels on every plate deeper than 8 bits. SDR to HDR runs on its own for a plate that holds values above 1.0; `S.deliver` holds the Finish menu's passes for the plate (`hdr`, the deliberate conversion), the fluid shot under the edits keeps them, and scenes save them (version 6; a version-5 scene's switch, on, becomes `deliver.hdr`).

**Live previews and stopping.** Live Preview patches every LTX pass (preview and full size, the clean plate pass's two stages, SDR to HDR, the fluid shot): a preview at every step, each naming its step and the pass's steps from the sampler's `sample_sigmas` (the page shows « step 3 of 8 », and the stage of the two-stage clean plate pass). At full size the latent is averaged first so the tiny decoder works at about twice the preview's size, and the SDR-to-HDR pass's ACEScct codes show through `mathops.acescct_preview` (Reinhard, then the sRGB curve). `showLive` shows a render's pass in the player: `#live`, an image over the frame, placed where zoom and pan put the frame. It is a looping picture of the whole shot, new at each step, and it goes when the pass ends and its result replaces it (`dropLive`). A pinned Render step, the wipe, O held, an edit in progress, a stroke or a stop hide it. With the Preview menu on Off, every workflow that has a live preview gets `live: 0` (`logic.liveEvery`), and none shows. A fluid shot fills the frame until its shot plays. When a job that sent previews ends, the page asks `POST /paintaplate/live/<prompt>` (`routes.clear_live`), which removes that prompt's WebP files from ComfyUI's temp folder. Esc follows `logic.escapeAction`: `stopGenerating` sets `S.halted`, cancels the render's and the fluid's jobs and keeps every finished step; `idle` waits, and Enter clears it. Stop, beside Generate while anything generates, does what Esc does. Cancel on the opening screen, or Esc, stops a plate that is opening (`cancelOpen`); Close plate stops every job, resets the frame caches and empties the page (`closePlate`), and ComfyUI keeps its models.

**The way back from the model space.** Out of `@model`, the composite undoes core's tone mapping with the plate's peak (`ocio.undo_tone`; the plate's conversion into the model space reads the plate's peak once and gives it as its second output, `peak`; the shot's return and Relight Transfer take it as a number, and `peak_of` stays for a first frame converted alone, in `ingest`), so new content comes back at the plate's levels. At a peak of 7.4, a grey of 0.18 came back 0.23 stops low and a white of 1.0 came back 0.97 stops low before 1.11.13; the error is now 0.00015 stops at most. Relight Transfer measures the light the same way (`ocio.out_of_model`, its input `peak_of`). A plate whose peak is at or under 1.0 gives the same bytes as before. A saturated colour above 1.0 keeps its luminance, not its saturation. The preview stays in the model space. Not measured on a GPU yet: `tests/hdr_plate.py` makes an HDR plate from a movie and measures an edit's level against the plate at the matte's seam.

## 7. The fluid shot

1. **A blank plate.** With no plate open, the page opens one at start, at the tab's settings (`?blank=0` starts empty). In the Open dialog, the Blank plate tab posts to `/paintaplate/blank`, which writes a black ProRes 4444 canvas in `input/paintaplate/blank`, once per size. Sides are multiples of 64 up to 1920; lengths are 8k + 1 frames, from 9 to 321; frame rates are 24, 25 or 50 fps. Two more options of the address serve the tests: `?seed=<n>` starts every new edit and every new fluid shot from seed n, so a run makes the same pictures again, and `?index=0` leaves the job index alone, so every job runs and is timed (`logic.askedSeed`, `logic.plateIdentity`).
2. **Keyframes.** The brush paints on frame 0, on the last frame, and on the 8k + 1 frames between (`snapKey`). Diamonds on the timeline drag between free slots; Ctrl+C and Ctrl+V copy a keyframe, Delete removes it, and onion skins show the keyframes around the playhead.
3. **Generate** (Enter, `generateFluid`). The `fluid` workflow runs one LTX 2.5 pass. Keyframe Video builds the control video (black frames with each keyframe at its frame). `LTXICLoRALoaderModelOnly` reads the LoRA's downscale factor and hands it to `LTXAddVideoICLoRAGuide`. The sampler is `euler_ancestral` with the 8 distilled sigmas at CFG 1, and the prompt is `ainvfxfluid, ` followed by your text prompt (`fluidPrompt`).
4. **The first edit.** Once made, the fluid shot is the plate the next edits are painted on: History shows it as edit 1, Fluid, under the others. Its pencil brings the keyframes and the text prompt back, its eye bypasses it (the blank plate under the edits), and it can try another seed or be removed. Another seed comes from its row's arrow or Ctrl+Enter, also while the shot is being made: the shot in progress stops, and the panel has no button for it. Hovering its row shows its first keyframe over the first frame, as hovering an edit's row shows its strokes. The edits on it keep their results by the plate they were made on (`recordOf`, `base`). When the plate under the edits changes (the fluid shot's eye, another seed), it reopens through `rebase`: `S.swap` holds the swap, and every pass waits for it before it reads the plate (`plateReady`). Each edit then takes its turn (`remakeAll`, `turn`): a result that holds for this plate and the edits under it comes back with no pass, with « reused » in the log, and any other edit runs again.
5. **Scenes.** Save scene keeps the scene on this ComfyUI (`/paintaplate/scenes`, in `output/paintaplate/scenes`): the plate and its file colour space, the OCIO config, display and view, the fluid shot's keyframes, text prompt and seed, and every edit with its strokes as drawn. Open plate > Scenes opens it again, or downloads it. The HUD, the status line and the log confirm the save with the scene file's full path, as the route answers it. When a scene of that name is saved already, Save scene asks before it replaces it: it reads the route's list and offers a free name in a field (`logic.freeName`, `logic.sceneName`) beside « Yes, replace it »; Esc saves nothing. A scene whose plate came from a blank plate is named at its first save: « Name this scene. », with « fluid_shot » in the field and a button that follows the field. The fluid shot keeps that name for the next saves (`S.fluid.sceneName`), and a scene opened from Scenes keeps its own. A scene keeps the build it was made with and the folders it uses under `output/paintaplate` (`logic.foldersIn`). Opened with another build (other code of the pack, of ComfyUI or of ComfyUI-LTXVideo, or other model files), its line says that every edit and render runs again; with the same build, every job comes from the job index, after a restart of ComfyUI too. View > « Clear unused cache… » asks `POST /paintaplate/cache` (`cache.py`) for the files of renders, edits and plates that no saved scene names and the page does not keep, says how much it clears, and clears them on « Yes, clear it »; an export and the scenes always stay. Strokes are saved in pixels of the working size the scene names, and drawn in one pass before any image is made from them: the same scene makes the same images, so the same jobs. A fluid scene keeps its blank plate in the model space, as Open plate makes it; its fluid shot, and for a 16-bit plate its SDR to HDR, are reused from the job index, so the EXR frames under the edits keep their files and every job on them is found again. Scenes of versions 1 and 2 still open, with the colour space read from the file.

Without `ainvfx-fluid.safetensors`, fluid shots switch off and the rest of the app works (`boot` sets `S.fluidReady`).

## 8. The Open dialog

Open plate has one tab per source: **ComfyUI files**, **Upload**, **Scenes** and **Blank plate**. ComfyUI files browses the input and output folders and their subfolders through `/paintaplate/browse`, which reads names, sizes and times only (`plateio.scan_folder`): numbered images are grouped into sequences named by frame pattern, an image alone is counted but not listed, and videos, animated images and saved scenes appear as they are. The page sorts and filters the list (`logic.browseItems`), draws `BROWSE_PAGE` items at a time as the list scrolls, and asks for a thumbnail only when it shows; the server makes at most four thumbnails at once and keeps each one in ComfyUI's temp folder. One click reads the item's details and guessed colour space (`/paintaplate/stat`); a double click opens it. At the input or output root, the route also returns the newest plates of the folders below (`routes.plates_below`: 60 at most, from at most 400 folders, Paint a plate's own folders left out), each listed with its folder.

When ComfyUI runs on this machine (`frames.sameMachine`), the ComfyUI files tab also takes the full path of a movie, a frame of a sequence or a folder of frames (design rule 10); a path in the input folder, or one that starts with `output:`, keeps its meaning. The page sends a typed path to `/paintaplate/stat` first: when the server cannot read it, the dialog stays open with the server's line, and when it can, the plate opens on that same answer. When ComfyUI runs on another machine, a note points to the Upload tab; `?remote` in the address shows that case, for the tests. A typed full path of a folder that holds no sequence lists it (`browse`), with the machine's folders as its trail, which starts with « This machine » (`logic.crumbs`; a Windows drive keeps its letter). Enter in a field does what Open does. ComfyUI files opens on Input each time, with its filter empty: the dialog keeps its tab and its order (`paintaplate.open`), not its folder.

| Node | What it does | Used by |
| --- | --- | --- |
| Load Plate | A video, a frame folder or a frame pattern at full precision: frames, alpha, spec, frame rate, frame count; optional 8k + 1 padding. A video's decoded frames are the plate, held once; an opaque plate's alpha is one frame, expanded | most workflows |

## 14. Known limits

These come from GPU tests on an RTX PRO 6000.

- An addition painted across a foreground object breaks up mid-shot, as a scooter painted over a fountain's rim does. Paint additions in open space.
- A body part removed with Clean, such as a head, can reappear in the result. Paint the new head over the old one instead.
- An explosion painted on a moving car drives off with it. Clean the car first.
- A name finds that object only: « floodlight » finds the lamp, and « floodlight pole » the pole.
- The paint matte takes what the shot changed within 1/16 of the width of the object's region. An effect that jumps further than that in one frame is not caught.
- A paint's matte ends where the shot's change falls under Follow Matte's threshold (0.1 above the frame's own level). The faint outer part of a paint that fades out, such as a glow or thin smoke, goes back to the plate there; the composite's grow and feather soften that step.
- After frames where the object is not seen, the matte searches up to 4 × 1/16 of the width around its last place: an object that comes back further away stays out. For an object that stands still in the scene, the search moves with the plate's background and does not grow while the plate covers the object's place. The plate is asked about every place it has shown, up to one frame's width on each side of the first frame.
- In a fluid shot, the painted colours win over the text prompt: paint a dusk sky in dusk colours.
- A video plate's review is 8-bit H.264 at crf 12, the same class as an 8-bit plate; a 10-bit video plate's review loses its extra bits in the viewer (the export keeps them). An image sequence's review is read at 960 px on the long side for playback.
- Model inputs come from the plate in the model space: values above 1.0 are tone-mapped into it, and edited pixels come back within 0 to 1 of it, as with core's conversion.

**The light brush and its request.** Light strokes are soft dabs at a fixed spacing (`logic.dabsAlong`), each stroke adding at most `LIGHT.flow` of its colour (`dabFlow`); shade strokes (a dark colour) go to their own layer, `d.shade`. On a Light edit the eraser takes light and shade away in soft dabs with the brush's spacing, reach and profile (`logic.rubDabs`, `rubLight`), so paint, erase and the same paint again give one paint; the edit's mask, laid as a hard line, is cut hard. A relight's request is the page's own: `logic.lightIntent` reads the strokes as intentions (each light's colour, strength, spread and place, and the shaded places) and adds the text prompt (`lightStrokes`, `templateCaption`). A paint and a light name a colour with one namer, `logic.colorName`: each swatch as its title names it, and « Warm light » as « warm white ». A small light painted inside the frame shows its source where it is drawn: its strokes of one colour that touch make one source, and the request places it with a row of Klein's layout table, as a paint's request places its object. A source is judged by its path, its points without the brush's width: the path spans under a fifth of the frame each way and stays 2% inside its edges, so a dab of any brush size is a source. A source is named by the text prompt when it names a kind of light (`logic.LIGHT_KINDS`), else « the sun » for a warm source in the top third of the frame. A stroke dragged across the frame is a wash, and a light at the frame's edge comes from outside the frame: neither shows a source, and it only relights. Klein gets the frame as it is and that prompt, with no second reference and no prompt writer; the strokes still show on the frame in the page. A shade stroke reaches Klein in words only: the request names the place where the shadow falls, and Klein darkens it as the scene's light would. Darkened in the stroke's shape, a shade would read as a streak of paint. The ComfyUI graph sends the same prompt.

Memory and time, each with what it was measured on:

- Opening a plate holds it once, padding included. Load Plate decodes a movie or an image sequence with the pack's own decoder (`plateio.decode_video`, `plateio.decode_frames`), which writes each frame into its place and makes core's pictures. Its array holds what the file's header says, up to `max_frames`, and grows or shrinks in place when the file holds another count. On a pod's CPU ComfyUI, a 1920 x 1080 plate of 121 frames takes 6.2 GB at its peak, against 17.4 GB with core's decoder, which holds the plate twice (its list of frames, then their stack), and ComfyUI keeps 5.1 GB after it, against 17.1 GB; a 3840 x 2160 plate takes 23.1 GB, against 65.9 GB. One float32 copy of the 1920 x 1080 plate is 2.80 GB. On a 16 GB GPU with 62.7 GB of RAM, core's decoder took 23.5 GB and kept 17.9 GB; the pack's own decoder is not measured there. `tests/open_probe.py` names the node that takes it, and its `--same` says whether two opens made the same pictures. Save Movie converts at most twice its workers ahead of x264 and makes its 8-bit frames in strips of 64 lines (`plateio.core_uint8`): 121 frames at 1280 x 720 take 233 MB above the level before on a CPU, against 628 MB without the strips. Neither is measured on a 16 GB GPU.
- A 3840 x 2160 plate of 121 frames at 50 fps ran paint, erase and light on a 96 GB GPU with 188 GB of RAM (a pod, 1.11.8). ComfyUI held up to 121 GB of RAM for the paint, 117 GB for the erase and 164 GB for the light, each in the full-size composite (`review`), then 91 to 138 GB in the export. One float32 copy of that plate is 11.2 GB.
- The page sets no limit on a plate's frames: every workflow gets the plate's own count. 121 frames is what is tested; a blank plate takes 9 to 321.
- On a 16 GB GPU, under the small memory profile, the cow case took 785 s at 1.11.8: 577 s of it in the full-size shot, which took 152 s with the same settings on a 96 GB GPU.
- **Numbers too far apart are not frames.** A group of numbered images is a frame sequence when at least one of every 100 numbers between its first and its last exists (`plateio.SPARSEST`). Sparser, the numbers count files: one frame per file. ComfyUI's mask editor names its files by the millisecond (`clipspace-mask-1791816680123.png`): taken as one sequence, such a group would make the Open dialog's thumbnail take all of ComfyUI's memory.
- **The cow behind the horse.** A painted object that stands still in the scene and passes behind something the plate holds leaves the paint matte while it is hidden and comes back into it where it comes out (`mathops.follow_matte`, from frame 8). When the object in front stood next to it on frame 0, it comes back 3 frames after it comes out in the test scene: its place's first look is also read inside the place, so what stood beside it is no part of it. A few pixels of what stands in front can enter the matte where the two touch. A piece of a still object that leaves the object's place, with what stands in front or alone, is left out, and the plate shows there: LTX can draw a painted cow walking away with the horse. An object that stands still for its first 8 frames and then moves by itself is lost the same way. An object that moves in the scene over its first 8 frames, or that is covered within them, is followed as before. On a 16 GB GPU at 1.11.12, the matte shrank with the cow as the horse covered it, was empty while the cow was hidden, and left out the cow's head that the preview gave the horse. After the horse passed, LTX drew the cow at its place again on 4 of 5 recordings, behind the fence, and the matte took it back with no mask from SAM, leaving out the fence rail in front of it (from frame 86 on the full-size pass). On the fifth, LTX walked the cow off with the horse, and the matte ends empty. Replayed on three recordings made on a pod too: the piece beside the horse's ear is out on every frame, and the cow drawn moving with the horse is out from the frame it has left the cow's place and its margin. `PAINTAPLATE_RECORD=<folder>` in ComfyUI's environment makes Follow Matte write what it was given (`mathops.record`): every pixel, in half floats, with the plate's first frame number. `mathops.follow_matte(**mathops.replay(file))` runs it again without a GPU, at the live run's size. A paint's recording of 121 frames at 960 x 544 weighs about 460 to 490 MB. A recording in the older format, reduced and in 8 bits, still replays, and its counts can differ from the live run's.
- **The paint zone.** SAM 3.1, prompted with the paint zone, returns the zone on its first 10 to 13 frames. On those frames the matte of an object that stands still is its place of frame 0, moved with the background: 1.1 to 1.3 times the cow on five recordings, where it held 3.9 to 5.4 times. LTX's cow can drift a few pixels on those frames; the matte then covers 76 to 90% of it, and the composite's growth covers the rest. SAM 3.1 can also shrink from the zone to the object over several frames: a mask of twice the object or more counts as the zone until the first mask under that, and on those frames the matte also keeps what the shot changed joined to the object's place. An object that moves inside its paint zone over its first 8 frames reads as standing still: the matte keeps to its place of frame 0, and loses it from frame 8. Replayed on five recordings; not run on a GPU.
- **A paint on part of an object.** SAM 3.1, prompted with the paint zone, can return the whole object under it. On an RTX PRO 6000, for a paint of 76 small strokes on the body of the horse of `horse.mp4` (the GPU case `horse_abdomen`: a paint zone of 12.4% of the frame, 2.97% of it changed on the first frame, 121 frames tracked at 960 x 544), the matte covered 19.0% of the frame on average while it followed the tracker's mask, with 98.3% of the horse's head inside it. Kept to what the shot changed beside the matte of the frame before, it covers 5.1%, the head stays out on every frame, and 97.3% of the changed pieces of 64 px or more stay in (97.4% before). On three other recordings (`horse_cow`, `horse_eagle`, `tos_arm`) the share of those pieces is the same before and after: 42.6%, 71.0% and 95.5%.
- **A soft plate.** `plate_move` reads a pan of 1 px per frame, at 128 px of width, as 0.33 px on a texture blurred at 2 px, 0.90 px at 1.5 px and 0.99 px at 0.7 px: its 25 px tiles are small for a soft texture (`tests/test_plate_soft.py` pins these readings). The horse plate reads well; a misty or defocused plate may not.
- An erased object that passes behind something is back in the matte when SAM 3.1 finds it again: until then it shows. A thin piece of it beside what stands in front can come back one frame late. At 1.11.12, on a 16 GB GPU, the matte of `horse_erase_barn` fell on every frame from 20 to 34, was empty on 58 to 100 while the horse hid the barn, and came back on frame 101. Once it is known to stand still, an erased object's place of frame 0, moved with the background, is in the matte wherever the plate shows it thick, seen by SAM or not: replayed on that recording, the barn comes back into the matte on frame 98. Its first 18 to 47 px in view, on frames 95 to 97, are too thin to enter the matte, and show.
- **The erase on a 16 GB GPU.** The second stage of the full-size clean plate pass (`cleanup`) starts from frames that Composite Frames makes one at a time: made whole, that start would hold the shot nine times at full size, about 25 GB for 121 frames at 1920 x 1088 by count, more than a cap of 52 GB of RAM leaves. On a 16 GB GPU under that cap, at 1.11.10, the stage was posted at 28.5 GB, held 31.8 GB before LTX loaded and 38.3 GB at its peak, and the case `horse_erase` ran to its end in 359 s.
- **An erase with no text prompt.** The prompt writer gets a box cut to the object (`logic.coreBox`). On `horse.mp4` (1920 x 1080, 121 frames, a 16 GB GPU) it names the barn under the stroke, and the barn goes on the first frame and in the whole shot (`horse_erase`, 354 s). A stroke on the tree, whose box takes in the barn's roof, is named the barn at the first look. The page then asks once more on the frame with all but the object dimmed (`logic.dimOutside`): asked that way by `tests/erase_probe.py` (its `dimmed` request), the writer removed the tree. The page's own second look removes the tree on the same plate and GPU (`horse_erase_tree`, 353 s), and its caption's headline says that the writer saw the dimmed frame. A second look's answer that removes the right object under a wrong name keeps that name in the caption and the log.
- **The saved ComfyUI graph of a Light edit.** It renders the relit result as the page did before SDR to HDR ran on the composite: with SDR to HDR on, a Light edit on a plate whose format holds nothing above 1.0 comes out SDR in the graph (`sceneGraph` has no step after the composite).
- **SDR to HDR's frames for a video or an integer plate.** When SDR to HDR's result goes out as EXR frames, every pixel is new: the export copies no source pixel there. For the plate's own format, the untouched pixels stay the source's own.
- The check of an erase (`logic.eraseCheck`) reads mean colours on cells of 4 pixels at the edit preview's size. The object reads as still there when under 30% of it moved by more than 24 levels, or when its edges held above 0.85. On 19 real first frames of `horse.mp4` a kept object reads 0 to 3% and 0.91 to 0.98, and a removed one 53 to 97% and -0.07 to 0.76: the margin on the edges is thin. The check can be wrong, so the page asks, with « Yes, render anyway », when it holds an erase back. The band beyond the object (`logic.bandBeyond`) catches a neighbour that Klein removed with the object: on those frames, the result that removed a fence with the barn moved 32% of the band's cells, and every other result 6.1% at most, so the threshold is 20% (`logic.BEYOND`). It rests on one plate's results: a real result between 6% and 20% passes without a question. The check compares colours, so another object of a different colour in the erased object's place reads as gone.
- **A pale band where an erased object was.** The clean plate pass erases the tracker's own mask, and the composite pastes Follow Matte's matte, which also holds the object's place of frame 0 where SAM 3.1 lost it. Where the two differ, the composite shows the plate's object, softened by LTX.
- x264 does not always make the same movie from the same frames: on a CPU with AVX-512, 17 frames of 960 x 540 at crf 12 gave up to 7 different movies in 12. The pictures are equal in quality. Tests compare movies written without loss, or frames.
- **Time estimates learn.** The Render panel's estimates come from what each step took the last time on this machine (`paintaplate.step-times` in the browser's storage, per step, size, frame count and memory profile; a step whose jobs are answered without running, from the job index or from ComfyUI's cache, keeps no time), else from `logic.stepGuess`: the 96 GB GPU's reference scaled to the plate and, on a 16 GB GPU, a lead in seconds per model family plus a factor per step (`logic.SLOWER`), measured on an RTX 4090 Laptop GPU (16 GB of VRAM, 52 GB of RAM) on one plate size (1920 x 1080, 121 frames). There, 30 of the 31 measured steps are within 25% of their announcement. SDR to HDR grows faster than the plate's pixels, so its announcement takes a power of the plate's scale (`SLOWER.small.grow`): it took 172 s at 1280 x 704 and 606 s at 1920 x 1088, 121 frames each. The full-size shot grows the same way. A composite also spends fixed seconds whatever its size (`SLOWER.small.fixed`). The full-size clean plate pass that starts from the preview's own pass announces its second stage alone (`logic.startsFromPreview`, `logic.stageTwoGuess`). With SDR to HDR on, the full-size composite and the export take longer than announced there (about 34 s and 15 s, against 20 s and 9 s). Other sizes are not measured.

The README lists what a person meets: on a plate whose camera travels, a paint's matte can lose the painted object on some frames, and a paint added over a Clean edit can show a faint shape of the removed object again, drawn by the shot and let in by the paint's matte; a painted object that a foreground object hides can raise « object left its place » although the composite is right; a shadow painted with Light comes out soft, and Relight Transfer can leave a rim along bright outlines; the check after Clean compares colours, so an object of another colour in the removed object's place passes it; on a paint's first frames, the matte can take in a change the shot made right beside the painted object, since it joins what the shot changed there (seen on a Half size preview); under 16 GB of VRAM, LTX's 256 px tiles leave a band where two tiles overlap; a Light edit with SDR to HDR can show a faint patch of light that floats over the plate (on the horse plate it is in the relit composite, before SDR to HDR, and a second plate, `plates/1280p_car.mp4`, shows none); a paint whose strokes cover a whole object that walks can lose its matte part-way, since the object moves inside its paint zone, the matte holds it as standing still and drops it once it leaves its place; a paint's matte can keep a few small spots within a zone of the edit, where the regenerated frame differs from the plate by a little more than the threshold; at Half size or Quarter size the preview's matte can cover parts of the object far from the edit, because the preview shot, compared with the plate at the tracking size, places fine details a few pixels away from the plate's, and the export uses the full-size matte.

## 15. Memory: the GPU, the frame caches and the trace

**The memory profile.** At page open, `warmAll` reads the GPU's VRAM and RAM from ComfyUI's `/system_stats` and sets `S.memoryProfile`: `{ name, why, does, warm, slots }` (`logic.memoryProfile`). The log says it in one message: the profile and the GPU, then what the page does on it.

| Profile | VRAM | What loads at start |
| --- | --- | --- |
| `small` | Under 24 GB (`MEMORY_FROM.medium`, 24e9 bytes: a 16 GB GPU reports about 17.2e9) | Nothing. Each model loads when an action needs it, so the prompt writer, Klein and LTX take turns |
| `medium` | From 24 GB (a 24 GB GPU reports about 25.7e9) | The edit models; LTX with the first shot |
| `large` | From 60 GB (`MEMORY_FROM.large`) | Every model, and they stay loaded |

From 16 GB of VRAM (`logic.WHOLE_FROM`, 16e9 bytes: a 16 GB GPU reports about 17.2e9, a 12 GB one about 12.9e9), every profile decodes each LTX frame whole (slot `tile` at `WHOLE`), encodes every IC-LoRA guide whole (`guide_tiled` false) and encodes the first stage of the full-size clean plate pass whole (slot `encode_tile` at `WHOLE`): « The decode's tiles » in section 6 says why. Under it, or when ComfyUI gives no VRAM size, LTX decodes and encodes in 256 px tiles and encodes its guides in tiles, and the small profile's line says so. One set of workflows serves every profile: `slots` fills the `tile`, `encode_tile` and `guide_tiled` slots, and `warm` names the workflows `warmAll` posts. `?memory=small` (or `medium`, `large`) in the address, or the `paintaplate.memory` setting, asks for a profile in place of the GPU's. The borders move with measurements: `tests/gpu_matrix.py` writes each case's peak VRAM and RAM. On a 96 GB GPU, asking for `small` cost 73 s on a 258 s case: the time goes to loading each family of models again after a free.

**The frame caches.** `FrameCache` (decoded frames) and `DeepFrames` (an image sequence's half floats) share one budget, set in View > Cache memory and kept in `localStorage` as `paintaplate.cache`. It is Auto by default, View > Cache memory > Custom… takes a size from 128 MB to 32 GB typed in MB or GB (`logic.memoryBytes`; 1 GB is 10^9 bytes), and `?cache=<MB>` sets it for a test. `planCaches` gives each cache of the sources on show its share and its frame size, again whenever the budget, the frame's size, the sources or the in and out points change (`frames.cachePlan`). A new budget alone keeps every cache's frame size: a larger budget only adds room, and a smaller one drops the frames of least use until the rest fit. A plan made again for other sources on show (the wipe, the pass on show) keeps a cache's size, and its frames, when the new size is within `CACHE_NEAR` (10%) of its own on each side (`frames.nearSize`). A new plate, other in and out points or a view that outgrows the frames plan the sizes again. When the frames route gives a source no frames, its `DeepFrames` stop, the viewer keeps the 8-bit movie, and the log says so once, in red (`logic.deepStopped`).

**Playback from memory.** Once every frame between the in and out points is in memory for each source the picture draws (`memoryReady`), playback runs on a clock, from memory. Until then it follows the videos. `S.memory` is that path: `true` from memory, `false` from the videos, `null` when nothing plays. `?stats=1`, or View > Playback statistics, writes one log line for each stretch played (`PlayStats`).

**The trace.** With `PAINTAPLATE_TRACE=1` in ComfyUI's environment, a middleware in `routes.py` (`trace`) writes one line when a request starts and one when it ends: its method and address, the seconds, and the memory the process holds. `TESTING.md` says how to read it.
