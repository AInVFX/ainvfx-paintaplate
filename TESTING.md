# Testing Paint a plate

One command runs the suite. A test whose package or tool is missing skips itself and says what to install. In CI (GitHub Actions sets `CI=true`) the same miss fails instead, so a broken install never passes as skipped.

```bash
pip install -r tests/requirements.txt
python -m unittest discover -s tests -v
```

Where the system Python refuses `pip` (Ubuntu, Debian), install into a virtual environment first: `python3 -m venv ~/.venvs/paintaplate && . ~/.venvs/paintaplate/bin/activate`. Every package in `tests/requirements.txt` has wheels for Python 3.12 to 3.14.

**`discover` also runs the page suite.** Outside CI, `test_ui_mock` runs every flow of `tests/ui_mock.py`, one per CPU: a few minutes on a workstation, more than a quarter of an hour on one CPU. Never run `python -m unittest discover`, or `python -m unittest test_ui_mock`, in a session with a time limit. To run the unit tests alone, name their modules from `tests/`; to run page flows, name them: `python tests/ui_mock.py --only start,open`.

## The page against the mock ComfyUI

`tests/mock_comfy.py --plate` serves the page with a stand-in ComfyUI: the same HTTP and WebSocket API, numpy instead of models, step previews, progress and interrupts, and the pack's own routes (the browser, thumbnails, scenes, OCIO, the job index, the download). `--plate` writes a 1280 x 704 example plate to `input/plates/desk.mp4`. The stand-in writes VP9 previews, because Playwright's Chromium cannot decode H.264; Chrome, Edge, Safari and Firefox can. Each job waits a little, as on a GPU, and `--speed 8` divides those waits by 8. The jobs run on a thread of their own, as ComfyUI runs its prompts beside its server: every route, `/mock/*` included, answers while a job writes its files (`mock_route` waits 5 s for an answer). Its log names each job and its time.

`python tests/ui_mock.py` runs the page's whole behaviour against it, flow by flow (set `PLAYWRIGHT_CHANNEL=chrome` to drive Google Chrome). A flow is one subject of the page. It runs in its own process, with its own mock ComfyUI and its own browser. So a flow starts from its own page load, a failure ends that flow only, and flows run side by side.

| Command | What it does |
| --- | --- |
| `python tests/ui_mock.py` | Every flow, one per CPU at a time, then a table: flow, checks, time, first failure. The exit code is 1 when a flow failed |
| `--list` | Names the flows |
| `--only keys,scene` | Runs the flows named. With `--jobs 1` their lines print as they come |
| `--jobs 4` | Four flows side by side (default: the number of CPUs). Each takes its own port, from `--port` up |
| `--speed 1` | The mock's jobs at their full simulated time (default: 8 times shorter) |
| `--limit 600` | The seconds a flow may take before it is stopped and counted as failed |
| `--shard 2/4` | The second of four parts of the flows, for machines side by side |
| `--json results.json` | Every flow's result in a file, which `test_ui_mock` reads |

The flows wait on what the page shows (an element's state, a line of the log), never on the clock. A new check never waits on the clock. The older flows still hold short fixed waits (56 calls of `wait_for_timeout` in `tests/flows` on 12 November), among them 0.6 s for the check that nothing starts by itself. The windows the mock holds open for the race checks keep their own time at any `--speed`: `/mock/slow`, `/mock/hold`, `/mock/oom` and the second after `/free`.

The mock's own routes, for the checks that need a window held open or a look at what the page asked for:

| Route | What it does |
| --- | --- |
| `POST /mock/slow` | The next `times` uploads wait `seconds` before they are read. `POST /mock/release` lets the held upload go on now |
| `POST /mock/hold` | The next `times` jobs that write `output`, or fill `slot`, last `seconds` each, at any `--speed`. An interrupt still ends them |
| `POST /mock/oom` | The next `times` jobs of `workflow` run out of GPU memory, with ComfyUI's own message |
| `POST /mock/card` | The card `/system_stats` reports from now on, in bytes: `{"vram": 17.2e9, "ram": 65.5e9}` is a 16 GB card with 61 GB of RAM, and `"ram_free"` is the RAM it reports as free. The memory profile's checks and `page_ram` use it |
| `POST /mock/version` | The version and the build `/paintaplate/version` answers from now on, as a ComfyUI restarted on other code would: it also drops every WebSocket, so open pages connect again. `page_version` uses it |
| `POST /mock/leave` | The next `times` edit jobs answer with the frame as it was, as a Klein pass that leaves its object. An edit is two jobs. `page_left` uses it |
| `POST /mock/writer` | The next `times` prompt-writer jobs answer `text`, as a writer that takes the stroke for another object. With `wide`, the writer removes another object whenever a locked box reaches it, and the painted one otherwise, as the laptop's did. `edit_name` and `edit_tight` use it |
| `POST /mock/snap` | The snap's answers take another object into two of its five masks, beside the stroke, as SAM 3.1 took in the horse's nose beside the barn. `edit_tight` uses it |
| `POST /mock/quit` | The mock stops at once, as a ComfyUI that the system stopped for its memory: nothing answers any more |
| `GET /mock/posts` | What each post asked for: its outputs, its `extra_data` (the previews it wants), and whether it sends a live preview |
| `GET /mock/events` | The timeline for the checks that need one: an out-of-memory failure, each `/free`, every fluid job posted, a held upload, and the start of a job that `/mock/hold` keeps open (« held ») |

| `page_tools` | `tests/flows/page_tools.py`. P, C and L pick Paint, Clean and Light, and B and E are free. A tap on X switches the eraser on or off, X held with no stroke leaves it as it was, and X held while a stroke is dragged rubs the stroke out, with the eraser off again when X comes up. |
| `page_ocio` | `tests/flows/page_ocio.py`. The OCIO menu: two headings say which part changes the result, each line shows its value, and the plate's line says where its value comes from. A new view asks nothing. With an edit that has a result, a new config and a new colour space each ask first: Cancel changes nothing and keeps the menu's tick, Change goes on, and the plate's line then ends with « override ». |
| `edit_name` | `tests/flows/edit_name.py`. An erase with no words that the prompt writer takes for another object asks for the object's name before Klein runs: the status line says so, the log says it once, no Klein pass and no shot run, and History's row says that the object is still there. Once the object is named, Generate runs the erase and its shot renders. |
| `edit_tight` | `tests/flows/edit_tight.py`. With no words, the prompt writer gets one box cut to the stroke and to what most of SAM's masks hold, without another object that two masks took in: the writer then removes the painted object, and it goes. |
| `page_graph` | `tests/flows/page_graph.py`. The saved ComfyUI graph: every image loader reads a file at the top of the input folder, the file is there, the graph's note names it, and the API graph agrees. |

Every module of `tests/flows` is a flow, named after its file (`tests/flows/README.md`). On 13 November 2026 the suite had 38 flows; on 11 November its 28 flows held 272 checks.

## CI

`.github/workflows/tests.yml` runs three kinds of job side by side on every push, none repeating another's tests, then a release job on `main`:

| Job | What it runs |
| --- | --- |
| Unit tests | The whole suite with no browser and no ComfyUI: the Python modules, the Node tests and the linters. |
| Page tests | `test_ui_mock`: the page against the mock ComfyUI, in four shards on four machines (`PAGE_SHARD`). Each shard runs its part of the flows, one per CPU. A failed shard leaves the others running. |
| Live tests | `tools/ci_comfyui.sh` builds ComfyUI and ComfyUI-LTXVideo at the pins on CPU, with empty model files from `tools/placeholders.py`; then `test_live` and the source check of `test_workflows`. No model runs: model workflows are cancelled once ComfyUI has validated them, and the browser test swaps them for stand-ins made of core nodes. |
| Release | On `main` only, once every job passes, each page shard included: a new `version` in `pyproject.toml` gets its Comfy Registry publish, its tag `v<version>` and its GitHub release (a pre-release before 1.0.0). Each step skips what is done already. |

pip downloads are cached, and the browser jobs drive the runner's own Google Chrome when it has one, so no browser is downloaded.

## On a GPU machine

These run the real models; `tools/runpod_start.sh` sets up a Runpod pod and starts ComfyUI, and with `PLATES=1` adds the example plates from the Hugging Face dataset `AInVFX/ainvfx-paintaplate` (`python get_plates.py` does it alone, on any machine).

- `tests/ui_live.py --url http://127.0.0.1:8188 --path plates/<shot> --think 8 --out <folder> --strokes '<json>' --channel chrome` drives the real page and records a timed mark for every stage, screenshots, the page's log and the downloaded zip. Each stroke is `[key, words, [[x, y], ...], brush size, options]`, with x and y from 0 to 1 on the frame; the options are `{"whole": false}` (an erase painted as is) and `{"color": "#d32f2f"}` (a swatch). `--fluid '<json>'` makes a fluid shot from a blank plate instead of opening a plate: `{"size": [1280, 704], "fps": 24, "frames": 121, "words": "...", "keys": [[frame, colour, [[x, y], ...], brush size], ...]}`, where a frame is 0, -1 for the last frame, or 8k + 1. Several strokes on one frame build one keyframe, so flat zones for sky and ground can sit under the fluid. With `--strokes`, the shot then becomes the plate and takes them. Playwright's own Chromium cannot play H.264: install Google Chrome with `python -m playwright install chrome` and pass `--channel chrome`. `--seed <n>` starts every new edit and every new fluid shot from that seed. A run with `--url` opens the page with `?index=0`: the page leaves its job index alone, so every job runs and is timed. When the page says that an erase left its object, the case ends there, as failed.
- `tests/gpu_bench.py` times single steps: `edit` (Klein previews and refine, `REFINE_STEPS`), `shot` (Ripple, replace against prepend), `export`, `mp4` (an H.264 copy of an EXR plate) and `anime` (a example plate made with FLUX 3 Image Klein and LTX 2.5).
- `tests/gpu_matrix.py --url http://127.0.0.1:8188 --comfy <ComfyUI folder> --out <folder> --cases quick` is the one GPU test, for a pod and for a laptop. Each case runs `tests/ui_live.py` on the real page, in Google Chrome. The script then writes `<out>/report.md`: the machine, then per case the time of each step, peak VRAM and RAM, out-of-memory retries, the memory profile, the paint matte's area on every frame against the first frame's, the previews received, and pass or fail. `quick` runs on `plates/horse.mp4`: a cow painted behind the fence, one erase, one light, then a fluid shot at 1280 x 704 x 121. `all` adds a 3840 x 2160 plate at 50 fps and a fluid shot at 1920 x 1088 at 50 fps. `--memory small`, `medium` or `large` asks the page for that memory profile, so the same case under two profiles shows what a profile costs. `--timeout` is `ui_live.py`'s: it waits twice that for an edit and 8 times that for a render. The default, 900, suits a 16 GB card; on a pod, pass `--timeout 300`. When ComfyUI has stopped, the cases left are not started: the report says « not run: ComfyUI had stopped » for each. `--fresh` frees ComfyUI before each case, so a case's peak RAM is its own; its first job then loads its models again. Each case holds its seed in `gpu_matrix.json` and paints its strokes as written, so a run asks for the same jobs as the run before; `--seeds 7,8,9` runs each case once per seed, and the report names the seed asked for and the seeds of the page's log. `--graph` also saves each case's scene as a ComfyUI graph in the case's folder. `horse_erase_barn`, outside `quick` and `all`, is `horse_erase` with its object named. `horse_saddle` (a saddle blanket painted on the horse's back) and `horse_bird` (an object that stands still, then leaves by itself), also outside both, give the matte its recordings. A stroke of `gpu_matrix.json` names its tool by its button's `data-tool` (paint, erase, light), which stays when a label or a key changes. Each case's folder also holds each node's seconds, from ComfyUI's WebSocket, and the report names the five longest nodes of every job of 30 s or more. The report also gives each step beside the time the page announced, the steps more than 25% from it, a fluid shot's steps, the page's figure for an erase (« N% of it changed ») and, without `--fresh`, a line saying that a case's first job can read the peak RAM the case before left. `--hdr` turns SDR to HDR on for every case, a case asks for it with `"hdr": true`, and the report then gives HDR Match's line, read from ComfyUI's own log. `hdr_cow`, outside `quick` and `all`, is `horse_cow` on the HDR test plate, which the test makes when it is missing. Each case with an edit also gets a sheet of pictures, shown in the report: the plate and the export around each edit, on the first frame, at a third, at two thirds and on the last frame. For a Clean edit, the sheet and the report give the page's verdict on the export's first frame: `logic.eraseCheck`, run with Node through `tests/erase_probe.py`, at the page's quick-pass size, inside the mask the page sent Klein. It reads gone, left, or « no verdict » and why. A case with `"expect": "name asked"` passes when the page asks for the object's name and neither Klein nor a shot ran: `horse_erase_tree`, outside `quick` and `all`. When ComfyUI stopped during a case, a job that its history lost takes its node names from `web/workflows/<job>.json`, and the report names the node that was running at the stop. Such a job has no row with its peaks: a row takes its times from ComfyUI's history. HDR Match's line is looked for after a render's SDR to HDR only. The report's GB are 2^30 bytes. The movie tests of `test_gpu_matrix` need PyAV and OpenEXR (`tests/requirements.txt`).
- `tests/open_probe.py horse.mp4 [--url http://127.0.0.1:8188] [--fresh] [--csv readings.csv] [--same <folder>]` opens one plate through the page's own `ingest` workflow on a running ComfyUI, and prints one row per node: the memory at its start, its peak, the memory at its end, its seconds. When ComfyUI is killed for its memory, the lines already printed name the node. Each probe prints the folder of its frame and its movie: with `--same` and the folder of an earlier probe, it says whether this open made the same pictures, the first frame and every frame of the playback movie, by their decoded pixels.
- `tests/erase_probe.py plates/horse.mp4 --out <folder>` asks for the first frame's erase seven ways on a running ComfyUI (`page`, `wide`, `dimmed`, `crop`, `named`, `as_words` and `own`), for three strokes, with the page's own workflows, the page's own `ingest` for the plate, and the page's own rules read from `web/logic.mjs` through Node. `page` is the box cut to the object, and `wide` the box of 1.11.13. It measures each result four ways, the page's rule among them, and writes a report, a sheet and the answers. No page runs; about 8 minutes on a 16 GB card.
- `tests/hdr_plate.py make --source <movie> --out <folder>` writes an HDR test plate from a movie: half-float EXR frames with the highlights lifted to a peak near 7. `tests/hdr_plate.py seam --plate <folder> --export <the export's zip>` measures an edit's level against the plate at the matte's seam, in stops, per band of the plate's luminance.
- `tests/decode_parity.py --comfy <ComfyUI folder> [--plates <files>] [--max-frames <n>]` compares Load Plate's decoder with core's, frame for frame, in ComfyUI's own Python. It must end with « DECODE SAME ». A path given to `--plates` that is not a file stops it before any work: one line, exit code 2. `tests/comfy_live.py` runs it, so a ComfyUI pin that changes core's pictures fails the live tests.
- `tests/object_info_fixture.py --url http://127.0.0.1:8188 --out <file>` writes the copy of `/object_info` for a scene's classes from a running ComfyUI: the true copy of `tests/js/object_info.scene.json`. That file is the laptop's copy, read from a running ComfyUI 0.44.2 on 13 November 2026 (70 classes); the `peak` output and input of Color Space (OCIO) and the `peak` input of Relight Transfer (1.11.15) were added to it by hand, until the laptop writes it again. `PLAYWRIGHT_CHANNEL=chrome python tests/graph_live.py --url http://127.0.0.1:8188 --graph <a saved scene's ComfyUI graph> --out <folder>` opens that graph in ComfyUI's own editor, names red nodes, nodes that overlap at the sizes ComfyUI draws and every value that differs from the API graph saved in the file, and takes a screenshot. Nothing is queued. Every run also checks that each image loader reads a file at the top of ComfyUI's input folder, named by the graph's note, and measures the layout: the canvas, and the links longer than 1,500 px. `python tests/graph_live.py --offline --graph <scene.comfyui.json>` checks a saved graph with no ComfyUI and no browser, with the classes of `tests/js/object_info.scene.json` and the sizes saved in the file; the values against the editor's graph need the live run.

## The trace: when ComfyUI's memory grows and no job runs

Start ComfyUI with `PAINTAPLATE_TRACE=1` in its environment. A middleware (`routes.py`, `trace`) then writes one line in ComfyUI's log when a request starts and one when it ends: its method and address, the seconds, and what the process holds (VmRSS). It sees every request, the pack's routes and ComfyUI's own. A front end's own file is said only when it is slow or heavy. One more line is written each time the memory has moved by half a GB, so growth between two requests shows. A request that starts and never ends is one that ran when ComfyUI stopped. It is off by default: nothing changes without the variable. On a pod, each start of `tools/runpod_start.sh` keeps the log of the ComfyUI that ran before as `comfyui.<date>-<time>.log`: after a stop, the trace is in that file.
