# Testing Paint a plate

One command runs the suite. A test whose package or tool is missing skips itself and says what to install. In CI (GitHub Actions sets `CI=true`) the same miss fails instead, so a broken install never passes as skipped.

```bash
pip install -r tests/requirements.txt
python -m unittest discover -s tests -v
```

Where the system Python refuses `pip` (Ubuntu, Debian), install into a virtual environment first: `python3 -m venv ~/.venvs/paintaplate && . ~/.venvs/paintaplate/bin/activate`. Every package in `tests/requirements.txt` has wheels for Python 3.12 to 3.14.

**`discover` also runs the page suite.** Outside CI, `test_ui_mock` runs every flow of `tests/ui_mock.py`, one per CPU: a few minutes on a workstation, more than a quarter of an hour on one CPU. Never run `python -m unittest discover`, or `python -m unittest test_ui_mock`, in a session with a time limit. To run the unit tests alone, name their modules from `tests/`; to run page flows, name them: `python tests/ui_mock.py --only start,open`.

## The page against the mock ComfyUI

`tests/mock_comfy.py --plate` serves the page with a stand-in ComfyUI: the same HTTP and WebSocket API, numpy instead of models, step previews, progress and interrupts, and the pack's own routes (the browser, thumbnails, scenes, OCIO, the job index, the download). `--plate` writes a 1280 x 704 example plate to `input/plates/desk.mp4`. The stand-in writes VP9 previews, because Playwright's Chromium cannot decode H.264; Chrome, Edge, Safari and Firefox can. Each job waits a little, as on a GPU, and `--speed 8` divides those waits by 8. Its log names each job and its time.

`python tests/ui_mock.py` runs the page's whole behaviour against it, flow by flow (set `PLAYWRIGHT_CHANNEL=chrome` to drive Google Chrome). A flow is one subject of the page. It runs in its own process, with its own mock ComfyUI and its own browser. So a flow starts from its own page load, a failure ends that flow only, and flows run side by side.

| Command | What it does |
| --- | --- |
| `python tests/ui_mock.py` | Every flow, one per CPU at a time, then a table: flow, checks, time, first failure. The exit code is 1 when a flow failed |
| `--list` | Names the flows |
| `--only keys,scene` | Runs the flows named. With `--jobs 1` their lines print as they come |
| `--jobs 4` | Four flows side by side (default: the number of CPUs). Each takes its own port, from `--port` up |
| `--speed 1` | The mock's jobs at their full simulated time (default: 8 times shorter) |
| `--limit 600` | The seconds a flow may take before it is stopped and counted as failed |
| `--shard 2/4` | The second of four parts of the flows, for machines side by side |
| `--json results.json` | Every flow's result in a file, which `test_ui_mock` reads |

The flows wait on what the page shows (an element's state, a line of the log), never on the clock. A new check never waits on the clock. The older flows still hold short fixed waits (56 calls of `wait_for_timeout` in `tests/flows` on 12 November), among them 0.6 s for the check that nothing starts by itself. The windows the mock holds open for the race checks keep their own time at any `--speed`: `/mock/slow`, `/mock/hold`, `/mock/oom` and the second after `/free`.

The mock's own routes, for the checks that need a window held open or a look at what the page asked for:

| Route | What it does |
| --- | --- |
| `POST /mock/slow` | The next `times` uploads wait `seconds` before they are read. `POST /mock/release` lets the held upload go on now |
| `POST /mock/hold` | The next `times` jobs that write `output`, or fill `slot`, last `seconds` each, at any `--speed`. An interrupt still ends them |
| `POST /mock/oom` | The next `times` jobs of `workflow` run out of GPU memory, with ComfyUI's own message |
| `POST /mock/card` | The card `/system_stats` reports from now on, in bytes: `{"vram": 17.2e9, "ram": 65.5e9}` is a 16 GB card with 61 GB of RAM, and `"ram_free"` is the RAM it reports as free. The memory profile's checks and `page_ram` use it |
| `POST /mock/quit` | The mock stops at once, as a ComfyUI that the system stopped for its memory: nothing answers any more |
| `GET /mock/posts` | What each post asked for: its outputs, its `extra_data` (the previews it wants), and whether it sends a live preview |
| `GET /mock/events` | The timeline for the checks that need one: an out-of-memory failure, each `/free`, every fluid job posted, a held upload, and the start of a job that `/mock/hold` keeps open (« held ») |

## CI

`.github/workflows/tests.yml` runs three kinds of job side by side on every push, none repeating another's tests, then a release job on `main`:

| Job | What it runs |
| --- | --- |
| Unit tests | The whole suite with no browser and no ComfyUI: the Python modules, the Node tests and the linters. |
| Page tests | `test_ui_mock`: the page against the mock ComfyUI, in four shards on four machines (`PAGE_SHARD`). Each shard runs its part of the flows, one per CPU. A failed shard leaves the others running. |
| Live tests | `tools/ci_comfyui.sh` builds ComfyUI and ComfyUI-LTXVideo at the pins on CPU, with empty model files from `tools/placeholders.py`; then `test_live` and the source check of `test_workflows`. No model runs: model workflows are cancelled once ComfyUI has validated them, and the browser test swaps them for stand-ins made of core nodes. |
| Release | On `main` only, once every job passes, each page shard included: a new `version` in `pyproject.toml` gets its Comfy Registry publish, its tag `v<version>` and its GitHub release (a pre-release before 1.0.0). Each step skips what is done already. |

pip downloads are cached, and the browser jobs drive the runner's own Google Chrome when it has one, so no browser is downloaded.

## On a GPU machine

These run the real models; `tools/runpod_start.sh` sets up a Runpod pod and starts ComfyUI, and with `PLATES=1` adds the example plates from the Hugging Face dataset `AInVFX/ainvfx-paintaplate` (`python get_plates.py` does it alone, on any machine).

- `tests/ui_live.py --url http://127.0.0.1:8188 --path plates/<shot> --think 8 --out <folder> --strokes '<json>' --channel chrome` drives the real page and records a timed mark for every stage, screenshots, the page's log and the downloaded zip. Each stroke is `[key, words, [[x, y], ...], brush size, options]`, with x and y from 0 to 1 on the frame; the options are `{"whole": false}` (an erase painted as is) and `{"color": "#d32f2f"}` (a swatch). `--fluid '<json>'` makes a fluid shot from a blank plate instead of opening a plate: `{"size": [1280, 704], "fps": 24, "frames": 121, "words": "...", "keys": [[frame, colour, [[x, y], ...], brush size], ...]}`, where a frame is 0, -1 for the last frame, or 8k + 1. Several strokes on one frame build one keyframe, so flat zones for sky and ground can sit under the fluid. With `--strokes`, the shot then becomes the plate and takes them. Playwright's own Chromium cannot play H.264: install Google Chrome with `python -m playwright install chrome` and pass `--channel chrome`.
- `tests/gpu_bench.py` times single steps: `edit` (Klein previews and refine, `REFINE_STEPS`), `shot` (Ripple, replace against prepend), `export`, `mp4` (an H.264 copy of an EXR plate) and `anime` (a example plate made with FLUX 3 Image Klein and LTX 2.5).
- `tests/gpu_matrix.py --url http://127.0.0.1:8188 --comfy <ComfyUI folder> --out <folder> --cases quick` is the one GPU test, for a pod and for a laptop. Each case runs `tests/ui_live.py` on the real page, in Google Chrome. The script then writes `<out>/report.md`: the machine, then per case the time of each step, peak VRAM and RAM, out-of-memory retries, the memory profile, the paint matte's area on every frame against the first frame's, the previews received, and pass or fail. `quick` runs on `plates/horse.mp4`: a cow painted behind the fence, one erase, one light, then a fluid shot at 1280 x 704 x 121. `all` adds a 3840 x 2160 plate at 50 fps and a fluid shot at 1920 x 1088 at 50 fps. `--memory small`, `medium` or `large` asks the page for that memory profile, so the same case under two profiles shows what a profile costs. `--timeout` is `ui_live.py`'s: it waits twice that for an edit and 8 times that for a render. The default, 900, suits a 16 GB card; on a pod, pass `--timeout 300`.
- `tests/open_probe.py horse.mp4 [--url http://127.0.0.1:8188] [--fresh] [--csv readings.csv] [--same <folder>]` opens one plate through the page's own `ingest` workflow on a running ComfyUI, and prints one row per node: the memory at its start, its peak, the memory at its end, its seconds. When ComfyUI is killed for its memory, the lines already printed name the node. Each probe prints the folder of its frame and its movie: with `--same` and the folder of an earlier probe, it says whether this open made the same pictures, the first frame and every frame of the playback movie, by their decoded pixels.

## The trace: when ComfyUI's memory grows and no job runs

Start ComfyUI with `PAINTAPLATE_TRACE=1` in its environment. A middleware (`routes.py`, `trace`) then writes one line in ComfyUI's log when a request starts and one when it ends: its method and address, the seconds, and what the process holds (VmRSS). It sees every request, the pack's routes and ComfyUI's own. A front end's own file is said only when it is slow or heavy. One more line is written each time the memory has moved by half a GB, so growth between two requests shows. A request that starts and never ends is one that ran when ComfyUI stopped. It is off by default: nothing changes without the variable. On a pod, each start of `tools/runpod_start.sh` keeps the log of the ComfyUI that ran before as `comfyui.<date>-<time>.log`: after a stop, the trace is in that file.
